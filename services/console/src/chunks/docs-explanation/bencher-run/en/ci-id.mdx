### `--ci-id <ID>`

<br />

Optional: Custom ID for posting results to CI.
Every job of a Project on a pull request shares one comment, with one Report row for each job.
With an ID, the row's label is its number and the ID (ex: `2 (microbench)`).
Until the job's Report exists, its row shows only the ID and no number (ex: `(microbench)`), as `Pending` while the job runs, and comes after the numbered rows.
Without an ID, the label is the number only, and the row appears once the job's Report exists.
By default, jobs share one row when they have the same combination of: Branch, Testbed, and [Adapter](/docs/explanation/adapters/),
along with [`--build-time`](#--build-time) and [`--file-size`](#--file-size-file) if set.
Setting a custom ID is useful when Bencher is being run multiple times on the same commit for the same Project, Branch, Testbed, and Adapter combination,
so that each run gets its own row.
For example, a `push` run and a `pull_request` run on the same branch share the head commit,
so give each run its own ID, or do not use `--github-actions` for the `push` run.
Otherwise, the runs share one row, which shows only one of them, and an older run writes nothing once a newer run holds the row.
The ID is also used in place of the Project name in the GitHub Check name (ie `Bencher Report (<ID>)`),
so each invocation gets a stable name that can be used as a separate required status check.
Requires: `--github-actions`
