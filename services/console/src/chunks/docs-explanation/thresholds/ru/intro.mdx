Пороги помогают фиксировать ухудшения производительности с Bencher.
Порог назначается уникальной комбинации:
[ветка][branch], [тестовый стенд][testbed], фильтр параметров, [Измерение][measure] и [метрика][metric].
Порог использует конкретный [тест][tests] для обнаружения ухудшений производительности.
Комбинация теста и его параметров называется моделью.
Модель должна иметь нижнюю границу, верхнюю границу или обе.

- Нижняя граница
  - Нижняя граница используется, когда меньшее значение указывает на ухудшение производительности,
  например, с Измерением Throughput.
- Верхняя граница
  - Верхняя граница используется, когда большее значение указывает на ухудшение производительности,
  например, с Измерением Latency.

Каждая граница используется для расчета предельного значения границы.
Затем каждая новая метрика, которую проверяет порог, сравнивается с каждым предельным значением границы
с использованием истории этой метрики для того же [варианта][variant].
Оповещение создается, когда новая метрика ниже предельного значения нижней границы или выше предельного значения верхней границы.

При [непрерывном тестировании производительности] (то есть при тестировании в CI) вам нужно будет создать пороги.
Используя подкоманду CLI <code><a href="/ru/docs/explanation/bencher-run/">bencher run</a></code>,
вы уже указываете ветку с [опцией `--branch`][branch option]
и тестовый стенд с [опцией `--testbed`][testbed option].
Таким образом, другие измерения, которые вам нужно указать, это Измерение с опцией `--threshold-measure`
и метрика этого Измерения для проверки с опцией `--threshold-metric`.
Чтобы проверять только некоторые варианты, добавьте фильтр параметров с опцией `--threshold-parameters`.
Затем вы можете использовать опцию `--threshold-test` для указания теста, который будет использоваться для этой метрики.
Опции `--threshold-min-sample-size`, `--threshold-max-sample-size` и `--threshold-window`
позволяют вам контролировать, какие данные используются в тесте.
Наконец, опции `--threshold-lower-boundary` и `--threshold-upper-boundary`
позволяют вам установить нижнюю и верхнюю границы.
Если вы хотите удалить все модели, которые не указаны,
вы можете сделать это с помощью флага `--thresholds-reset`.

- Если порог не существует, он будет создан для вас.
- Если порог существует, и указанная модель та же, то модель игнорируется.
- Если порог существует, и указанная модель другая, тогда для порога создается новая модель.
- Если порог существует и сброшен, текущая модель удаляется из порога.

<summary>BMF версия 0</summary>

В [BMF версии 0][bmf versions] порог назначается ветке, тестовому стенду и Измерению, и он проверяет метрику `value` каждого бенчмарка.
Используйте `--threshold-measure` без `--threshold-metric`:
`--threshold-metric` и `--threshold-parameters` останавливают `bencher run` с ошибкой до того, как что-либо будет отправлено,
и эта ошибка называет `bencher project update --bmf-version 1` для перевода Проекта на версию 1.
