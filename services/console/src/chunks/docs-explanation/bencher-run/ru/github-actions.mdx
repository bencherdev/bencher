### `--github-actions <GITHUB_TOKEN>`

<br />

Необязательно: Установите токен аутентификации API GitHub. Самый удобный способ сделать это - использовать [переменную окружения `GITHUB_TOKEN` в GitHub Actions][github token] (например, `--github-actions ${{ secrets.GITHUB_TOKEN }}`).

Результаты будут добавлены к head-коммиту как проверка GitHub с именем:

1. `Bencher Report (<ID>)`, если задана [опция `--ci-id`](#--ci-id-id)
2. `Bencher Report (<ИМЯ ПРОЕКТА>)` для существующих проектов
3. `Bencher Report` для динамических проектов [`--ci-on-the-fly`](#--ci-on-the-fly) (пока проверка выполняется)

Это требует, чтобы у токена были [полномочия `checks` с разрешениями на `write`][github token permissions]. Если проверку GitHub не удается создать, `bencher run` запишет предупреждение в журнал и продолжит работу.

Когда `bencher run` используется как часть запроса на вытягивание, результаты также будут добавлены в запрос как комментарий. Все задания Проекта в запросе на вытягивание используют этот один общий комментарий, с разделом для каждого задания. Это требует, чтобы у токена были [полномочия `pull-requests` с разрешениями на `write`][github token permissions]. Результаты также всегда будут добавлены в сводку задания. С [флагом `--detach`](/ru/docs/explanation/images/#--detach) отсоединенный запуск не публикует комментарий и не пишет сводку задания, а [подключение с помощью `--job`](/ru/docs/explanation/images/#--job-uuid) завершает проверку GitHub, которую он запустил (см. [опцию `--ci-callback-token`](#--ci-callback-token-token)).

Раздел каждого задания называется по [опции `--ci-id`](#--ci-id-id), если она задана, иначе по Ветке, Тестовой среде и Адаптеру задания. Если разделов два или больше, комментарий показывает строку сводки для каждого раздела с его статусом (`Pending`, число предупреждений, `No Alerts` или `Failed`), одну таблицу всех предупреждений и результаты каждого раздела в сворачиваемом блоке, который открыт, если в разделе есть предупреждения. Каждое задание сохраняет свою проверку GitHub и свою сводку задания, поэтому имена проверок GitHub и обязательные проверки статуса не меняются. Задание, чей коммит больше не является head-коммитом запроса на вытягивание, оставляет комментарий без изменений. Если токен не может прочитать запрос на вытягивание, то задание запишет предупреждение в журнал и напишет комментарий без проверки head-коммита.

Чтобы найти другие разделы, `bencher run` получает список проверок GitHub для head-коммита, что уже разрешают указанные выше полномочия `checks` с разрешениями на `write`. Если задание не может создать или завершить свою проверку GitHub, не может определить, какому GitHub App она принадлежит, или не может получить список проверок GitHub, то оно опубликует комментарий только со своими результатами. Комментарии Проекта от более ранней версии `bencher run` заменяются: первое задание, которое пишет общий комментарий, обновляет самый старый из них и удаляет остальные. При записи общего комментария задание обновляет или удаляет только комментарии, опубликованные GitHub App, которому принадлежит его проверка GitHub, то есть ботом `github-actions` при использовании `GITHUB_TOKEN`.

[github token]: https://docs.github.com/ru/actions/security-guides/automatic-token-authentication
[github token permissions]: https://docs.github.com/ru/actions/security-for-github-actions/security-guides/automatic-token-authentication#permissions-for-the-github_token

> 🐰 Если вы запускаете внутри контейнера Docker в GitHub Action, вам нужно будет передать следующие переменные окружения и смонтировать путь, указанный в `GITHUB_EVENT_PATH`:
> - `GITHUB_ACTIONS`
> - `GITHUB_EVENT_NAME`
> - `GITHUB_EVENT_PATH`
> - `GITHUB_SHA`
> - `GITHUB_API_URL` (GitHub Enterprise Server только)
