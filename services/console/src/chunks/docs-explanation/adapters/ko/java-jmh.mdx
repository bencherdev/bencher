## ☕️ Java JMH

Java JMH 어댑터(`java_jmh`)는 [JSON 형식(즉, `-rf json`)](https://github.com/openjdk/jmh/blob/master/jmh-core/src/main/java/org/openjdk/jmh/results/format/ResultFormatType.java)의 [Java Microbenchmark Harness (JMH)](https://github.com/openjdk/jmh) 출력을 입력으로 받습니다.
이 JSON 출력은 파일로 저장되므로, `bencher run` CLI의 `--file` 옵션으로 그 파일 경로를 지정해야 합니다.

<Java />

벤치마크 이름은 JMH가 붙인 벤치마크 이름입니다(즉, `org.example.MyBenchmark.hash`).
각 `@Param`은 값을 문자열로 하는 매개변수가 되고,
모드는 `@mode` 매개변수가 됩니다(즉, `thrpt`, `avgt`, `sample`, `ss`).
매개변수가 8개를 넘는 변형은 보고서의 warning에서 건너뛴 것으로 집계됩니다.

주 점수는 그 모드의 측정에 수집됩니다:
`thrpt`는 `throughput`(즉, `operations / second (ops/s)`),
`avgt`, `sample`, `ss`는 각각 `latency`, `sample-time`, `single-shot-time`(즉, `nanoseconds (ns)`)입니다.
그 메트릭은 JMH의 99.9% 구간이 붙은 `mean`(즉, `mean_ci99_9_lower`와 `mean_ci99_9_upper`)과
JMH가 보고하는 백분위수 `min`, `median`, `p90`, `p95`, `p99`, `p99_9`, `p99_99`, `p99_999`, `p99_9999`, `max`입니다.

주 점수와 같은 단위의 보조 결과(`@AuxCounters` 연산 카운터 또는 `@Group` 멤버)는
같은 측정의 별도 변형에 수집되며, 그 레이블이 `@label` 매개변수가 됩니다.
`-prof gc`의 결과 같은 그 밖의 모든 보조 결과는 그 레이블의 이름을 딴 측정이 되며, 단위는 JMH가 기록한 그대로입니다.
JMH가 합산하는 보조 결과는 `mean`과 그 구간 대신 `sum` 메트릭을 가집니다.
유한한 값이 없는 보조 결과는 버려지며,
주 점수의 측정과 같은 레이블(즉, `latency`)을 가진 보조 결과는 건너뛴 것으로 집계됩니다.

먼저 `median` 메트릭에 임계값을 설정하세요(`--threshold-metric median`).

<details>
<summary>BMF 버전 0</summary>

BMF 버전 0에서는 `latency`와 `throughput` 측정(즉, `nanoseconds (ns)`와 `operations / second (ops/s)`)이 모두 수집될 수 있습니다.
`lower_value`와 `upper_value`는 각각 평균(즉, `value`)의 신뢰 구간 하한과 상한입니다.
