## 服务器消息

从服务器发送到 Runner 的消息。

| Event    | 描述                                       | 负载                                                          |
| -------- | ------------------------------------------------- | ---------------------------------------------------------------- |
| `ack`    | 确认收到的消息                   | 可选的 `job`（`job` 消息的 UUID）                               |
| `job`    | 将 Job 的一次执行分配给 Runner           | 该次执行的 UUID、Job 的 Spec、作为一次迭代且带有 Job 超时剩余部分的 Job 配置，以及一个短期有效的 OCI 拉取令牌 |
| `no_job` | 轮询超时到期且没有可用的 Job    | 无                                                             |
| `cancel` | Job 已取消或超时；停止执行 | 无                                                             |
| `update` | Runner 应自我更新到新版本    | `version`、`url`（下载 URL）和 `checksum`（SHA-256）        |

`job` 消息中的 OCI 拉取令牌为该次执行生成，且从不存储。
它的作用域限定在 Job 所属的单个 project，仅可拉取，且短期有效，
因此一个被攻陷的 Runner 只能拉取发送给它的 Job 对应 project 的 Image。

在 `stable` 更新通道上，当 Runner 的版本与服务器版本不同时，会发送 `update`。
在 `canary` 更新通道上，`version` 为 `canary`，
并且当 Runner 自行报告的二进制校验和
与已发布的滚动 canary 构建不同时，会发送 `update`。
