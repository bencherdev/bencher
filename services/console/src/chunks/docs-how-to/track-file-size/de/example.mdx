Wenn Sie ein Skript unter `./my_build_script.sh` hätten, das Ihr Binär an dem Pfad `./path/to/my_binary` erstellt,
dann könnten Sie die Größe dieser Binärdatei mit
<code><a href="/de/docs/explanation/bencher-run/">bencher run</a></code>
und [dem `json` Adapter][json adapter] verfolgen.
Das würde sowohl mit [einem Benchmark-Befehl][bencher run] als auch ohne einen solchen funktionieren.

In diesem Beispiel ist der Schlüssel `my_binary` der Dateiname der Binärdatei.
Er wird als Name des [Benchmarks][benchmark] verwendet.
Der Schlüssel `my_binary` verweist auf eine Liste mit einem Eintrag,
und das `measures`-Objekt dieses Eintrags enthält den Schlüssel `file-size`.
`file-size` ist der Slug für die integrierte File Size [Measure][measure].
Die File Size Measure wird nicht standardmäßig für alle Projekte erstellt.
Jedoch, wenn Sie die File Size Measure verwenden,
wird sie automatisch für Ihr Projekt erstellt.
Das File Size Measure-Objekt enthält die `value`-[Metrik][metric]
mit der Dateigröße in Bytes, `42.0`.

Die Dateigröße wird immer in ganzen Byte-Schritten angegeben.
Das heißt, sie wird _niemals_ eine Dezimalstelle wie `42.5` haben.
Da BMF JSON jedoch eine breite Palette möglicher Werte unterstützen muss,
verwendet es Gleitkommazahlen anstelle von Ganzzahlen.
