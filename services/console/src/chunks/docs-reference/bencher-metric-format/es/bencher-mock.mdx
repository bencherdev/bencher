## `bencher mock`

El subcomando de la CLI `bencher mock` se usa para generar datos JSON simulados en el Bencher Metric Format (BMF).
Escribe [BMF versión 1][bmf versions] a menos que se indique lo contrario:
cada [Medida][measure] de cada [Benchmark][benchmark] tiene una [Métrica][metric], `value`,
y cada Benchmark tiene una Variante sin Parámetros.
No lee la versión de su Proyecto, así que un Proyecto de versión 0 necesita [`--bmf-version 0`](#--bmf-version-bmf_version).

### `--seed <SEED>`

La semilla para el generador de números pseudoaleatorios.
Si no se especifica, se usará una semilla aleatoria.

### `--count <COUNT>`

El número de [Benchmarks][benchmark] simulados a generar.

### `--measure <MEASURE>`

La [Medida][measure] que se usará para cada [Benchmark][benchmark].
Se pueden especificar varias Medidas usando la opción `--measure` varias veces.
Por defecto se usa la Medida incorporada `latency`.

### `--parameters <PARAMETERS>`

Los [Parámetros][parameters] de una Variante que se generará para cada Benchmark, como un objeto JSON (ej: `--parameters '{"size": 64}'`).
Cada conjunto de Parámetros crea una Variante de cada Benchmark,
y se pueden especificar varios conjuntos usando la opción `--parameters` varias veces.
Si no se especifica, cada Benchmark tiene una Variante sin Parámetros.
Acepta el mismo JSON que [la opción `--threshold-parameters`][threshold parameters] de `bencher run`,
y no se puede usar con `--bmf-version 0`.

### `--bmf-version <BMF_VERSION>`

La versión de BMF que se escribirá, `0` o `1`.
El valor por defecto es `1`.
En la versión 0, cada Medida tiene un `value`, un `lower_value` y un `upper_value`.

### `--pow <POW>`

La potencia de 10 que se usará para las [Métricas][metric] simuladas.
El valor por defecto es `1`.

### `--fail`

Fallar durante la ejecución.

### `--flaky`

Fallar de forma intermitente durante la ejecución.

### `--help`

Imprimir el mensaje de ayuda.
