
### `--start-point-idempotency-key <KEY>`

<br />

Использует указанный ключ как ключ идемпотентности для [флага `--start-point-reset`][start point reset option].
Ключом может быть любой текст.
Установите либо опцию `--start-point-idempotency-key`, либо переменную окружения `BENCHER_START_POINT_IDEMPOTENCY_KEY`.
Если `--start-point-reset` не установлен или ключ пуст, эта опция игнорируется.

- Если ни у одной [Головы][head] `ветки` нет этого ключа, сброс создаст новую Голову `ветки` с этим ключом.
- Если у Головы `ветки` уже есть этот ключ, будет использована эта Голова, и `ветка` не будет сброшена повторно,
  даже если начальная точка изменилась или эта Голова с тех пор была заменена.

При запуске в GitHub Actions ключом по умолчанию является текущая попытка запуска workflow.
Все задания одного запуска workflow используют одну Голову `ветки`, а повторный запуск workflow создает новую Голову.
Последующие шаги того же запуска workflow, которые сбрасывают `ветку`, также используют эту Голову, поэтому задайте другой ключ для шага, которому нужно снова сбросить `ветку`.
Для других CI-провайдеров установите в качестве ключа значение, одинаковое для всех заданий одного запуска пайплайна
(например, `--start-point-idempotency-key "$CI_PIPELINE_ID"` в GitLab CI/CD).

Например, если workflow запускает матрицу из трех заданий, каждое из которых использует `--branch feature_branch --start-point main --start-point-reset --start-point-idempotency-key run-abc123`,
то:

1. Первое задание, отправившее отчет, создаст новую [Голову][head] `feature_branch` из `main` с ключом идемпотентности `run-abc123`
2. Два других задания используют ту же Голову `feature_branch`, так как у нее есть ключ идемпотентности `run-abc123`
3. Результаты всех трех заданий отображаются вместе в `feature_branch`
