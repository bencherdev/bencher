## 다국어 능통자 Claude

2023년에 저는 Bencher 문서를 영어, 중국어, 스페인어, 브라질 포르투갈어, 러시아어, 일본어, 프랑스어, 독일어, 한국어의 9개 언어로 제공하기로 했습니다. 이 아홉 개 언어는 어떻게 골랐냐고요? GitHub 문서가 제공되는 언어들이었기 때문에, 그 정도면 충분히 괜찮은 근사치라고 생각했습니다. 유일한 문제는 제가 유창하게 하는 언어가 영어뿐이라는 것이었습니다. 그래서 GPT-4에게 문서 번역을 맡겼습니다. 당시 GPT-4의 컨텍스트 윈도는 고작 8k 토큰이었습니다. 그래서 모든 문서 페이지를 8k 토큰보다 작은 "청크"로 쪼개야 했습니다. 그다음에는 청크를 번역하고, 청크가 수정된 뒤에는 아주 자주 다시 번역하는 일을 처리할 CLI 도구를 만들어야 했습니다.

이 과정은 매우 지루하고 오류가 나기 쉬웠습니다. 아주 명시적인 시스템 프롬프트 지시를 줘도 모델이 import 경로를 망가뜨리거나 모든 내용을 Markdown 블록 한 겹 안에 또 집어넣어 버리곤 해서, 번역된 파일을 손으로 고쳐야 했습니다. 왠지 모르게 특히 일본어에서 그랬습니다.

Opus 4.5와 함께 Claude Code를 쓰기 시작하자, 이 모든 문제가 사라졌습니다. 이제는 에이전트가 그냥 알아서 합니다. 무엇이 청크가 되는지에 대한 규칙이 코드베이스에 있고, Claude는 그저 그 규칙을 따릅니다. Bencher Bare Metal의 기술 문서를 작성할 때도, 청크로 나누는 일과 번역을 조율하는 일은 Claude가 그냥 처리했습니다. 이제 컨텍스트 크기가 페이지 전체를 다루고도 남을 만큼 커졌지만, 저는 청크가 있는 쪽이 좋습니다. 변경 사항을 격리하는 데 도움이 되어서, 수정할 때 페이지에서 관련된 부분만 다시 번역되기 때문입니다.
