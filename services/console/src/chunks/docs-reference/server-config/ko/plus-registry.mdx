### `plus.registry`

이 섹션은 OCI(Open Container Initiative) 레지스트리 스토리지 구성을 지정합니다.
Bencher는 OCI 호환 컨테이너/아티팩트 레지스트리로 작동할 수 있습니다.

이 섹션이 구성되지 않은 경우, Bencher는 데이터베이스 파일 옆의
`registry` 디렉토리에 로컬 파일시스템 스토리지를 사용합니다.
이는 개발 및 단일 인스턴스 배포에 적합합니다.

여러 인스턴스가 있는 프로덕션 배포 또는 내구성을 위해서는
S3 호환 스토리지를 구성하세요.

두 가지 스토리지 `scheme`이 있습니다:
- `file`: 로컬 파일시스템에 OCI 아티팩트 저장 (기본값)
    - `path`: (선택사항) 레지스트리 데이터 디렉토리. 기본값은 데이터베이스 파일 옆의 `registry` 디렉토리입니다.
- `s3`: S3 호환 블롭 스토리지에 OCI 아티팩트 저장
    - `bucket`: 버킷 이름
    - `path`: (선택사항) 버킷 내 키 접두사. 앞, 뒤, 반복되는 슬래시는 제거되므로 `registry`, `registry/`, `/registry` 모두 `registry` 아래에 저장됩니다.
    - `endpoint`: (AWS: 선택사항 | 비AWS: 필수) 스토리지 엔드포인트
    - `region`: (선택사항) 버킷 지역. AWS에는 필수입니다. 기본값은 `auto`이며, S3 호환 스토리지가 기대하는 값입니다.
    - `access_key_id`: S3 액세스 키
    - `secret_access_key`: S3 비밀 액세스 키
    - `chunk_size`: (선택사항) 저장하기 전 업로드 데이터를 버퍼링하기 위한 최소 청크 크기(바이트). 기본값: 5 MB.
      HTTP 요청 본문은 작은 네트워크 프레임(일반적으로 8~64 KB)으로 도착합니다. 버퍼링 없이는 각 프레임이 별도의 객체로 저장되어 레이어당 수천 개의 객체가 생성됩니다. 이 값은 S3 멀티파트 업로드 최소 파트 크기와도 일치합니다.

미완료 멀티파트 업로드를 중단하는 버킷 수명 주기 규칙을 설정하세요. Blob 업로드 완료 도중 충돌이 발생하면 미완료 업로드가 남으며, 서버는 이를 중단하지 않습니다.

이전에 슬래시로 시작하거나 끝나는 `path`를 구성했다면 업그레이드 전에 기존 객체를 정규화된 접두사로 옮기세요. `path`가 `registry/`이면 키가 `registry//<project>/...` 아래에 저장되었지만 이제는 `registry/<project>/...` 아래에 저장됩니다. `A-Za-z0-9._-/` 이외의 문자를 포함하는 `path`는 저장되는 키에서 퍼센트 인코딩되므로(`team#1`은 `team%231`이 됩니다), 이전 릴리스가 그러한 접두사 아래에 저장한 데이터도 동일하게 옮겨야 합니다.

|      이름      |                  예시                  | 기본값 |  필수  |                    설명                     |
| :------------: | :------------------------------------: | :----: | :----: | :-----------------------------------------: |
|      url       | "https://registry.bencher.example.com" | "http://localhost:6610" | 아니오 | OCI 레지스트리 액세스를 위한 API 서버의 외부 접근 가능 URL. |
|    storage     |               \{ ... \}                |  ---   | 아니오 | 레지스트리 스토리지 백엔드를 지정합니다. 생략 시 로컬 파일. |
| storage.scheme |                 "s3"                   |  ---   |   예   | 스토리지 `scheme`을 지정합니다. 다른 모든 `storage` 키는 위 목록을 참조하세요. |
| upload_timeout |                  3600                  |  3600  | 아니오 | 업로드 세션 타임아웃(초). 오래된 업로드는 새 업로드 시작 시 정리됩니다. |
| max_body_size  |               1073741824               | 1073741824 | 아니오 | Blob 및 매니페스트 업로드의 최대 본문 크기(바이트). 이 제한을 초과하는 요청은 413 Payload Too Large로 거부됩니다. 기본값: 1 GiB. |
