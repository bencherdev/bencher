## `--threshold-metric <METRIC>`

<br />

Используйте указанное имя [Метрики][metric] для порога.
В BMF версии 1 порог проверяет одну Метрику своего Измерения по имени, например `median`, `p99` или `value`.
Например, чтобы использовать порог для медианы Измерения Latency,
вы могли бы написать `--threshold-measure latency --threshold-metric median`.
Чтобы выбрать, какую Метрику проверять в первую очередь, посмотрите Метрики, которые записывает [каждый адаптер оснастки для тестирования][adapters].
Метрики, которые проверяют пороги Измерения, становятся его столбцами в [комментарии к запросу на вытягивание][github actions] и в выводе `bencher run`.

Если хотя бы у одного порога есть Метрика или фильтр параметров, Метрика нужна каждому порогу,
и `bencher run` останавливается с ошибкой, которая называет порог без Метрики.
`--threshold-measure` вовсе без `--threshold-metric` не задает порог:
запуск все равно сохраняется, а его Отчет выдает замечание о том, что порог пропущен, с подсказкой использовать `--threshold-metric`.
В BMF версии 0 `--threshold-metric` останавливает `bencher run` с ошибкой до того, как что-либо будет отправлено.
