### `--callback-body <JSON>`

<br />

オプション: コールバックリクエストのJSONボディを設定します。
このオプションは、[`--callback-url`オプション](#--callback-url-url)が設定されている必要があります。
`--callback-body`を指定しない場合、ボディはJobのレポートで、`GET /v0/projects/{project}/reports/{report}`が返すものと同じJSONです。
レポートはJobをUUID（`job`）で示しますが、Jobの状態は含みません。
Jobが失敗したかどうかを知るには、受信側で`GET /v0/projects/{project}/jobs/{job}`を使ってJobを読み取るか、ボディで`{{ job.status }}`を送信してください。
非公開プロジェクトでは、このレポートにはプロジェクトの非公開の結果が含まれるため、信頼できる受信側にのみ送信してください。

ボディ内の文字列値が次のプレースホルダーのいずれかと完全に一致する場合、その値として送信されます：

| プレースホルダー     | 値                                                     |
| -------------------- | ------------------------------------------------------ |
| `{{ job.uuid }}`     | JobのUUID                                              |
| `{{ job.status }}`   | Jobの終了状態：`processed`、`failed`、または`canceled` |
| `{{ report.uuid }}`  | レポートのUUID                                         |
| `{{ project.uuid }}` | プロジェクトのUUID                                     |
| `{{ project.slug }}` | プロジェクトのスラッグ                                 |
| `{{ report }}`       | レポート全体                                           |

波括弧の内側の空白は省略できるため、`"{{job.uuid}}"`も使えます。
各値はJSON文字列ですが、`{{ report }}`だけはレポートそのもので、
`--callback-body`を指定しない場合のボディと同じJSONであり、同じ非公開の結果を含みます。
そのため、`"{{ report }}"`だけのボディは`--callback-body`を指定しない場合と同じで、
`{"event": "bencher", "report": "{{ report }}"}`はレポートを独自のエンベロープで包みます。
`{{ report }}`はボディに1回だけ含めることができます。
それ以外の文字列、すべてのキー、それ以外の値はそのまま送信されます。
長い文字列の中のプレースホルダー（例：`"Job {{ job.uuid }}"`）はただのテキストで、分岐もないため、
結果が必要な受信側は`{{ job.status }}`を読み取ります。
`{{`で始まり`}}`で終わるのに、それ以外の名前を指定した文字列はエラーになり、空文字列になることはありません。
ボディは最大64 KiBで、各プレースホルダーは最長の値で、`{{ report }}`は0として数えます。
Jobを送信する前に`bencher run`がボディをチェックし、サーバーも再度チェックします。
