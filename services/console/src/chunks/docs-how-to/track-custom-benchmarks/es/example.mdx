En este ejemplo, la clave `benchmark_name` sería el nombre de un [Benchmark][benchmark].
Un Benchmark puede identificarse por su nombre, slug o UUID.
La clave `benchmark_name` apunta a una lista de entradas,
y cada entrada tiene un objeto `measures`.
El objeto `measures` puede contener múltiples nombres, slugs o UUIDs de [Medida][measure] como claves.
Si el valor especificado es un nombre o slug y la Medida no existe, se creará automáticamente.
Sin embargo, si el valor especificado es un UUID, entonces la Medida ya debe existir.
En este ejemplo, `latency` es el slug de la Medida integrada Latency.
Cada Proyecto tiene por defecto una Medida Latency (es decir, `latency`) y una Medida Throughput (es decir, `throughput`),
que se miden en `nanosecond (ns)` y `operations / second (ops/s)` respectivamente.
Cada objeto de Medida asocia nombres de [Métrica][metric] con sus valores.
Cuando tu arnés de benchmark informa un único resultado para una Medida,
nombra su Métrica `value`.

En este ejemplo, el objeto de Medida `latency` contiene una Métrica `value` de `88.0`.

Una entrada también puede tener un objeto `parameters`, como `{"size": 64}`.
Cada conjunto de [Parámetros][parameters] es su propia [Variante][variant] del Benchmark,
así que un Benchmark puede tener varias Variantes.
Una entrada sin `parameters` es la Variante del Benchmark sin Parámetros.
