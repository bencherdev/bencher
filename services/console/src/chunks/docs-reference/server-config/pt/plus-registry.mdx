### `plus.registry`

Esta seção especifica a configuração de armazenamento do registro OCI (Open Container Initiative).
O Bencher pode funcionar como um registro de contêineres/artefatos compatível com OCI.

Se esta seção não estiver configurada, o Bencher usará armazenamento em sistema de arquivos local
em um diretório `registry` adjacente ao arquivo de banco de dados.
Isso é adequado para desenvolvimento e implantações de instância única.

Para implantações de produção com múltiplas instâncias ou para durabilidade,
configure o armazenamento compatível com S3.

Há dois `scheme`s de armazenamento:
- `file`: Armazenar artefatos OCI no sistema de arquivos local (padrão)
    - `path`: (Opcional) Diretório para os dados do registro. Por padrão, um diretório `registry` adjacente ao arquivo de banco de dados.
- `s3`: Armazenar artefatos OCI em qualquer armazenamento de blob compatível com S3
    - `bucket`: Nome do bucket
    - `path`: (Opcional) Prefixo de chave no bucket. Barras iniciais, finais e repetidas são removidas, portanto `registry`, `registry/` e `/registry` armazenam todos sob `registry`.
    - `endpoint`: (AWS: Opcional | Não-AWS: Obrigatório) Endpoint de armazenamento
    - `region`: (Opcional) Região do bucket. Obrigatório para AWS. Por padrão `auto`, que é o esperado pelos armazenamentos compatíveis com S3.
    - `access_key_id`: Chave de acesso do S3
    - `secret_access_key`: Chave de acesso secreta do S3
    - `chunk_size`: (Opcional) Tamanho mínimo do fragmento em bytes para armazenamento em buffer dos dados de upload antes de salvar. Padrão: 5 MB.
      Os corpos de requisição HTTP chegam como pequenos frames de rede (tipicamente 8 a 64 KB). Sem armazenamento em buffer, cada frame se torna um objeto separado, criando milhares de objetos por camada. Este valor também corresponde ao tamanho mínimo de parte para uploads multipart do S3.

Defina uma regra de ciclo de vida do bucket que aborte uploads multipart incompletos. Uma falha no meio da conclusão de um upload de blob deixa um, e o servidor não o aborta.

Se você configurou anteriormente um `path` que começava ou terminava com uma barra, mova os objetos existentes para o prefixo normalizado antes de atualizar. Um `path` de `registry/` armazenava chaves sob `registry//<project>/...` e agora as armazena sob `registry/<project>/...`. Um `path` contendo qualquer caractere fora de `A-Za-z0-9._-/` é codificado em porcentagem na chave armazenada (`team#1` torna-se `team%231`), portanto os dados armazenados sob tal prefixo pela versão anterior precisam da mesma mudança.

|      Nome      |                Exemplo                 | Padrão | Obrigatório |                  Descrição                   |
| :------------: | :------------------------------------: | :----: | :---------: | :------------------------------------------: |
|      url       | "https://registry.bencher.example.com" | "http://localhost:6610" |     Não     | A URL externamente acessível do servidor API para acesso ao registro OCI. |
|    storage     |               \{ ... \}                |  ---   |     Não     | Especifica o backend de armazenamento do registro. Arquivos locais se omitido. |
| storage.scheme |                 "s3"                   |  ---   |     Sim     | Especifica o `scheme` de armazenamento. Para todas as outras chaves de `storage`, veja a lista acima. |
| upload_timeout |                  3600                  |  3600  |     Não     | Timeout da sessão de upload em segundos. Uploads obsoletos são limpos ao iniciar novos uploads. |
| max_body_size  |               1073741824               | 1073741824 |     Não     | Tamanho máximo do corpo em bytes para uploads de blobs e manifestos. Requisições que excedam este limite são rejeitadas com 413 Payload Too Large. Padrão: 1 GiB. |
