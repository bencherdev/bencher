### t-test

A t-test Test (`t_test`) measures the [prediction interval](https://en.wikipedia.org/wiki/Prediction_interval) (PI) for how likely it is that
a new Metric is above or below the mean of your historical Metrics using a [Student's t-test](https://en.wikipedia.org/wiki/Student's_t-test).

t-test Tests work best when:
- There are no extreme differences between benchmark runs
- Benchmark runs are totally independent of one another
- The number of iterations for a single benchmark run is less than 10% of the historical Metrics

For t-test Tests, prediction intervals are expressed as a decimal cumulative percentage.
If a new Metric is below a certain left-side cumulative percentage (Lower Boundary)
or above a certain right-side cumulative percentage (Upper Boundary) for your historical Metrics an Alert is generated.
Either a Lower Boundary, Upper Boundary, or both must be set.

- #### t-test Lower Boundary
  - A t-test Test Lower Boundary can be any positive decimal between `0.5` and `1.0`.
Where `0.5` represents the mean and `1.0` represents all possible left-side values (-∞).
It is used when a smaller value would indicate a performance regression.
  - For example, if you used a t-test Test with a Lower Boundary of `0.977`
and you had `25` historical Metrics with a mean of `100` and a sample standard deviation of `10`,
the Lower Boundary Limit would be `78.54` and
any value less than `78.54` would generate an Alert.
- #### t-test Upper Boundary
  - A t-test Test Upper Boundary can be any positive decimal between `0.5` and `1.0`.
Where `0.5` represents the mean and `1.0` represents all possible right-side values (∞).
It is used when a greater value would indicate a performance regression.
  - For example, if you used a t-test Test with an Upper Boundary of `0.977`
and you had `25` historical Metrics with a mean of `100` and a sample standard deviation of `10`,
the Upper Boundary Limit would be `121.46` and
any value greater than `121.46` would generate an Alert.
- #### t-test Boundaries across a Report
  - For a Project at BMF version 1, a t-test Boundary covers the whole Report.
An Upper Boundary of `0.99` means that an unchanged Report generates an Upper Boundary Alert at most 1 time in 100, however many Lines it has.
Bencher divides that chance equally across every check on that side of the Report: each Threshold, on each Line it checks, in each iteration.
A Line with too few historical Metrics to check still takes its share.
  - For example, a Report with `200` Lines and an Upper Boundary of `0.99` checks each Line at `0.99995`.
For a normal distribution, that moves each Line's Upper Boundary Limit from about `2.33` to about `3.89` standard deviations above the mean.
  - For a Project at BMF version 0, a t-test Boundary covers each Line on its own.
A Report with `200` Lines and an Upper Boundary of `0.99` generates about `2` false Upper Boundary Alerts.
