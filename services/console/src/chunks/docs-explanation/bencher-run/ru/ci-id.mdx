### `--ci-id <ID>`

<br />

Необязательно: Пользовательский идентификатор для отправки результатов в CI. Все задания Проекта в запросе на вытягивание используют один общий комментарий, и идентификатор задает название раздела задания в этом комментарии. С идентификатором раздел задания отображается как `Pending`, пока задание выполняется. Без него раздел появляется, как только создан Отчет задания. По умолчанию раздел задания называется по комбинации: Ветка, Тестовая среда и [Адаптер](/ru/docs/explanation/adapters/), а также [`--build-time`](#--build-time) и [`--file-size`](#--file-size-file), если они заданы. Установка пользовательского идентификатора полезна, когда Bencher запускается несколько раз на одном и том же коммите для той же комбинации Проекта, Ветки, Тестовой среды и Адаптера, чтобы у каждого запуска был свой раздел. Например, запуск по `push` и запуск по `pull_request` в одной ветке используют один и тот же head-коммит, поэтому задайте каждому запуску свой идентификатор или не используйте `--github-actions` для запуска по `push`. Иначе может появиться только раздел более нового задания, а другое задание ничего не пишет. Идентификатор также используется вместо имени Проекта в имени проверки GitHub (например, `Bencher Report (<ID>)`), поэтому каждый запуск получает стабильное имя, которое можно использовать как отдельную обязательную проверку статуса. Требуется: `--github-actions`
