## Messages du Runner

Messages envoyés du Runner vers le serveur.

| Event       | Description                                       | Charge utile                                                            |
| ----------- | ------------------------------------------------- | ----------------------------------------------------------------------- |
| `ready`     | Le Runner est inactif et demande un Job           | `poll_timeout` optionnel (1-900 s) et métadonnées `runner` (`os`, `arch`, `version`, `channel` de mise à jour optionnel et `checksum` du binaire optionnel), ainsi que l'état `health` optionnel des disques |
| `paused`    | Le Runner est inactif mais n'accepte aucun Job tant que ses motifs de pause persistent ; le serveur maintient l'interrogation et répond `no_job` | `reasons` (chacun avec un `kind` : `raid` ou `maintenance`), `since` et tous les champs de `ready` |
| `running`   | La préparation du Job est terminée et le benchmark démarre | Aucune                                                          |
| `heartbeat` | Signal de vie périodique (environ une fois par seconde) | Aucune                                                            |
| `completed` | Le benchmark s'est terminé avec succès            | `job` (l'UUID du message `job`) et `results` (la sortie de l'exécution) |
| `failed`    | Le benchmark a échoué                             | `job` (l'UUID du message `job`), `results` et `error`                   |
| `canceled`  | Accuse réception d'une annulation depuis le serveur | `job` (l'UUID du message `job`)                                       |

L'UUID d'un message `job` désigne cette exécution, et non le Job.
Le Runner le renvoie, de sorte qu'un résultat désigne exactement son exécution,
même lorsqu'il est renvoyé après le départ d'une autre exécution du même Job.
