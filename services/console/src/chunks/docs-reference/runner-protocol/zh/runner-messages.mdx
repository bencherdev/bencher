## Runner 消息

从 Runner 发送到服务器的消息。

| Event       | 描述                                       | 负载                                                                 |
| ----------- | ------------------------------------------------- | ----------------------------------------------------------------------- |
| `ready`     | Runner 空闲并请求一个 Job           | 可选的 `poll_timeout`（1-900 秒）和 `runner` 元数据（`os`、`arch`、`version`、可选的更新通道 `channel` 和可选的二进制校验和 `checksum`），以及可选的磁盘健康状况 `health` |
| `paused`    | Runner 空闲，但在暂停原因消除之前不接受 Job；服务器保持轮询并以 `no_job` 应答 | `reasons`（每项带有 `kind`：`raid` 或 `maintenance`）、`since` 以及 `ready` 的全部字段 |
| `running`   | Job 设置完成，基准测试正在启动 | 无                                                                  |
| `heartbeat` | 周期性存活信号（约每秒一次）  | 无                                                                    |
| `completed` | 基准测试成功完成              | `job`（`job` 消息的 UUID）和 `results`（该次运行的输出）          |
| `failed`    | 基准测试失败                              | `job`（`job` 消息的 UUID）、`results` 和 `error`                       |
| `canceled`  | 确认来自服务器的取消       | `job`（`job` 消息的 UUID）                                               |

`job` 消息的 UUID 指代该次执行，而不是 Job。
Runner 会原样返回它，因此结果能准确指向其执行，
即使在同一 Job 的另一次执行发出之后再重新发送也是如此。
