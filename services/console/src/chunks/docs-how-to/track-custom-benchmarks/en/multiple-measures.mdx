## Multiple Measures

In [Bencher Metric Format (BMF) JSON][bmf]
the `measures` object of a [Benchmark][benchmark] entry can contain multiple [Measure][measure] names, slugs, or UUIDs as keys.
If the value specified is a name or slug and the Measure does not already exist, it will be created for you.
However, if the value specified is a UUID then the Measure must already exist.
Each Measure object maps [Metric][metric] names to their values.

<BmfMultiExample />

In this example, the `latency` Measure object contains a `value` Metric of `88.0`,
and the `throughput` Measure object contains a `value` Metric of `5.55`.

You can use [the `bencher mock` CLI subcommand][bencher mock]
with [the `--measure` option][measure option]
to generate mock BMF data with multiple Measures.
We will use it as a placeholder for your own custom benchmark runner.
Using <code><a href="/docs/explanation/bencher-run/">bencher run</a></code>
and [the `json` adapter][json adapter]
we can track our benchmarks with multiple Measures with the following command:

If your benchmark harness reports more Measures than you want to track,
use [the `--measure` option][run measure option] of <code><a href="/docs/explanation/bencher-run/">bencher run</a></code>
to keep only the Measures you name.
Every other Measure is dropped before it is stored.
This is different from the `--measure` option of `bencher mock`,
which sets the Measures that `bencher mock` generates.
