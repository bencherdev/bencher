## 재해 복구

데이터 손실을 방지하기 위해 Bencher는 내장된 재해 복구 솔루션을 제공합니다. 재해 복구를 사용하려면 서버에 있는 조직 중 최소 하나에 유효한 [Bencher Plus _Enterprise_][pricing] 라이선스가 있어야 하며, 재해 복구가 구성된 서버는 유효한 라이선스가 없으면 시작을 거부합니다. 실행 중인 서버는 마지막 라이선스가 만료된 후에도 다시 시작할 때까지 복제를 계속합니다. 그 라이선스의 유예 기간 첫날부터 서버는 언제 시작을 거부할지 알려 주는 오류를 매일 로그에 기록합니다.

지원되는 복제 스키마:

- `file`: 로컬 파일 경로로 복제
- `s3`: S3 호환 블롭 스토리지로 복제

Bencher 자체 호스팅 API 서버의 재해 복구를 설정하려면 API 서버 구성의 [ `plus.disaster_recovery` 섹션][plus disaster recovery]을 사용하세요.

재해 복구가 구성된 서버를 중지하려면 중지 신호(`SIGTERM` 또는 `SIGINT`)를 API 서버 프로세스에만 보내세요. 그러면 API 서버는 처리 중인 요청을 마친 뒤 복제를 중지하고, 복제는 종료하기 전에 마지막 변경 사항을 복제합니다. 두 번째 중지 신호가 복제 프로세스(`litestream`)에 직접 전달되면 그 마지막 복제가 취소되어 마지막 변경 사항이 손실될 수 있습니다. `docker stop`은 중지 신호를 API 서버 프로세스에만 보냅니다. systemd에서는 중지 신호가 API 서버 프로세스에만 전달되도록 유닛에 `KillMode=mixed`를 설정하세요.
