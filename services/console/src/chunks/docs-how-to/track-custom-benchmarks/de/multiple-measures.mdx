## Mehrere Measures

Im [Bencher-Metrik-Format (BMF) JSON][bmf] kann das `measures`-Objekt eines [Benchmark][benchmark]-Eintrags mehrere [Measure][measure]-Namen, -Slugs oder UUIDs als Schlüssel enthalten. Wenn der angegebene Wert ein Name oder Slug ist und die Measure noch nicht existiert, wird sie für Sie erstellt. Wenn der angegebene Wert jedoch eine UUID ist, muss die Measure bereits existieren. Jedes Measure-Objekt ordnet [Metrik][metric]-Namen ihren Werten zu.

Dies ist ein Beispiel für BMF JSON mit mehreren Measures:

In diesem Beispiel enthält das `latency` Measure-Objekt eine `value`-Metrik von `88.0`,
und das `throughput` Measure-Objekt enthält eine `value`-Metrik von `5.55`.

Sie können das [CLI-Unterkommando `bencher mock`][bencher mock] mit der [Option `--measure`][measure option] verwenden, um gefälschte BMF-Daten mit mehreren Measures zu generieren. Wir verwenden es als Platzhalter für Ihren eigenen benutzerdefinierten Benchmark-Runner. Mit <code><a href="/de/docs/explanation/bencher-run/">bencher run</a></code> und dem [Adapter `json`][json adapter] können wir unsere Benchmarks mit mehreren Measures mit dem folgenden Befehl verfolgen:

<RunCmdMultiExample />

Wenn Ihr Benchmark-Harness mehr Measures meldet, als Sie verfolgen möchten,
verwenden Sie die [Option `--measure`][run measure option] von <code><a href="/de/docs/explanation/bencher-run/">bencher run</a></code>,
um nur die Measures zu behalten, die Sie nennen.
Jede andere Measure wird verworfen, bevor sie gespeichert wird.
Das unterscheidet sich von der Option `--measure` von `bencher mock`,
die festlegt, welche Measures `bencher mock` generiert.
Dieser Befehl generiert zum Beispiel beide Measures und verfolgt nur `latency`:
