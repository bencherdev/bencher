Self-Hosted Runner 是一个由你自己运行和管理的 [Bare Metal Runner][bare metal]，
而不是使用 Bencher 托管的 On-Demand 或 Dedicated Runner。
你将 `runner` 二进制文件指向某个 Bencher API 服务器，
它便会在你自己的硬件上认领并执行 [Job][job]。

在以下场景中自托管 Runner 是一个不错的选择：

- 在 Bencher Cloud 未提供的特定硬件上运行基准测试
- 将基准测试工作负载保留在你自己的网络或气隙（air-gapped）环境内
- 端到端运行 [Bencher Self-Hosted][bencher self hosted]

本指南将逐步介绍如何注册 Runner、用 [Spec][spec] 描述其硬件、
将两者关联起来，以及启动 `runner` 二进制文件。
关于 Runner、Spec、Sandbox 和 Job 如何协同工作的概念性概述，
请参阅 [Bare Metal 概述][bare metal]。

> 🐰 Firecracker 沙箱需要 Linux 5.14 或更高版本，启用 [KVM][kvm]，并在 `/sys/fs/cgroup` 提供可写的 cgroup v2 层级，
> 并且 Runner 必须以 `root` 身份运行。
> 无论 CPU 核心数量多少，每个沙箱 Job 都在 `/sys/fs/cgroup/bencher` 下自己的 cgroup 中运行，并为其启用 `cpuset`、`memory` 和 `pids` 控制器。
> Runner 通过该 cgroup 的 `cgroup.kill` 终止 Job 的进程，而较旧的内核没有它：在这些内核上，Runner 会在启动时退出；若以 `--danger-allow-no-sandbox` 启动，则每个沙箱 Job 都会失败。
> 运行每个沙箱 Job 的 Firecracker 进程都会以非特权用户的身份被限制在 chroot 中，
> 而构建这种限制所需的权限，仅仅启用 KVM 是无法获得的。
> 仅服务于非沙箱化 Spec 的 Runner 可以在任何受支持的主机上运行。
