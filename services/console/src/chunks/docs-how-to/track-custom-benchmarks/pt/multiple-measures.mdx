## Múltiplas Medidas

No [Formato de Métrica Bencher (BMF) JSON][bmf]
o objeto `measures` de uma entrada de [Benchmark][benchmark] pode conter múltiplos nomes, slugs ou UUIDs de [Medida][measure] como chaves.
Se o valor especificado for um nome ou slug e a Medida ainda não existir, ela será criada para você.
No entanto, se o valor especificado for um UUID, a Medida deve já existir.
Cada objeto de Medida associa nomes de [Métrica][metric] aos seus valores.

Neste exemplo, o objeto Medida `latency` contém uma Métrica `value` de `88.0`,
e o objeto Medida `throughput` contém uma Métrica `value` de `5.55`.

Você pode usar [o subcomando CLI `bencher mock`][bencher mock]
com [a opção `--measure`][measure option]
para gerar dados BMF simulados com múltiplas Medidas.
Usaremos isso como um espaço reservado para seu próprio executor de benchmark personalizado.
Usando <code><a href="/pt/docs/explanation/bencher-run/">bencher run</a></code>
e o [adaptador `json`][json adapter]
podemos rastrear nossos benchmarks com múltiplas Medidas com o seguinte comando:

<RunCmdMultiExample />

Se o seu harness de benchmark reporta mais Medidas do que você quer rastrear,
use [a opção `--measure`][run measure option] do <code><a href="/pt/docs/explanation/bencher-run/">bencher run</a></code>
para manter apenas as Medidas que você nomear.
Todas as outras Medidas são descartadas antes de serem armazenadas.
Isso é diferente da opção `--measure` do `bencher mock`,
que define as Medidas que o `bencher mock` gera.
