## Ciclo de Vida do Job

Cada Job passa por um conjunto fixo de estados conforme é reivindicado, executado e processado.

| De        | Para        | Gatilho                                                                |
| --------- | ----------- | ---------------------------------------------------------------------- |
| pending   | claimed     | Um Runner reivindica o Job                                             |
| pending   | canceled    | Um usuário cancela o Job                                               |
| claimed   | running     | O Runner envia `running`                                               |
| claimed   | failed      | O Runner envia `failed`                                                |
| claimed   | unknown     | O servidor perde o contato com o Runner                                |
| claimed   | canceled    | Um usuário cancela o Job                                               |
| running   | completed   | O Runner envia `completed`                                             |
| running   | failed      | O Runner envia `failed`                                                |
| running   | unknown     | O servidor perde o contato com o Runner                                |
| running   | canceled    | Um usuário cancela o Job, ou o timeout rígido do Job é excedido        |
| unknown   | completed   | O Runner envia `completed`                                             |
| unknown   | failed      | O Runner envia `failed`                                                |
| unknown   | canceled    | Um usuário cancela o Job, ou o timeout rígido do Job é excedido        |
| completed | processed   | O servidor processa os resultados com sucesso                          |
| completed | failed      | O servidor não consegue processar os resultados                        |
| completed | unknown     | Na inicialização, o servidor descobre que os resultados armazenados foram perdidos |

`processed`, `failed` e `canceled` são terminais: um Job `failed` ou `canceled` nunca muda de estado novamente.
`completed` é quase-terminal:
`completed` transiciona para `processed` assim que os resultados são analisados, para `failed` se não puderem ser processados, ou para `unknown` se na inicialização o servidor descobrir que foram perdidos.
`unknown` significa que o servidor perdeu o contato com o Runner e ainda não conhece o resultado.
Ele é resolvido quando o Runner se comunica novamente, com o resultado que envia,
ou como `canceled` quando o prazo do Job passa.
Toda transição usa um filtro de status em sua atualização no banco de dados,
de modo que um Job que foi modificado concorrentemente é relido em vez de sobrescrito.
