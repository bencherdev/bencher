### `--github-actions <GITHUB_TOKEN>`

<br />

オプション: GitHub API認証トークンを設定します。
これを行う最も便利な方法は、[GitHub Actions `GITHUB_TOKEN` 環境変数][github token]を使用することです（例：`--github-actions ${{ secrets.GITHUB_TOKEN }}`）。

結果は、次の名前のGitHubチェックとしてヘッドコミットに追加されます：

1. [`--ci-id`オプション](#--ci-id-id)が設定されている場合は`Bencher Report (<ID>)`
2. 既存のプロジェクトの場合は`Bencher Report (<プロジェクト名>)`
3. [`--ci-on-the-fly`](#--ci-on-the-fly)で作成されるプロジェクトの場合は`Bencher Report`（実行中のみ）

これにはトークンが[`checks` スコープに対する`write`権限][github token permissions]を持っている必要があります。
GitHubチェックを作成できない場合、`bencher run`は警告をログに記録して続行します。

`bencher run`がプルリクエストの一部として使用されると、結果はコメントとしてプルリクエストにも追加されます。
これにはトークンが[`pull-requests` スコープに対する`write`権限][github token permissions]を持っている必要があります。
結果は常にジョブサマリーにも追加されます。
[`--detach`フラグ](/ja/docs/explanation/images/#--detach)を指定すると、デタッチした実行はコメントを投稿せず、ジョブサマリーも書き込みません。[`--job`によるアタッチ](/ja/docs/explanation/images/#--job-uuid)が、開始されたGitHubチェックを完了します（[`--ci-callback-token`オプション](#--ci-callback-token-token)を参照）。

[github token]: https://docs.github.com/ja/actions/security-guides/automatic-token-authentication
[github token permissions]: https://docs.github.com/ja/actions/security-for-github-actions/security-guides/automatic-token-authentication#permissions-for-the-github_token

> 🐰 GitHub Action内でDockerコンテナを実行している場合、以下の環境変数を渡し、`GITHUB_EVENT_PATH`で指定されたパスをマウントする必要があります：
> - `GITHUB_ACTIONS`
> - `GITHUB_EVENT_NAME`
> - `GITHUB_EVENT_PATH`
> - `GITHUB_SHA`
> - `GITHUB_API_URL` (GitHub Enterprise Server のみ)
