### `--ci-id <ID>`

<br />

Необязательно: Пользовательский идентификатор для отправки результатов в CI. Все задания Проекта в запросе на вытягивание используют один общий комментарий, с одной строкой Отчета для каждого задания. С идентификатором подписью строки служат ее номер и идентификатор (пример: `2 (microbench)`). Пока Отчет задания не существует, его строка показывает только идентификатор без номера (пример: `(microbench)`), со статусом `Pending`, пока задание выполняется, и идет после пронумерованных строк. Без идентификатора подписью служит только номер, а строка появляется, как только Отчет задания существует. По умолчанию задания используют одну строку, если у них одинаковая комбинация: Ветка, Тестовая среда и [Адаптер](/ru/docs/explanation/adapters/), а также [`--build-time`](#--build-time) и [`--file-size`](#--file-size-file), если они заданы. Установка пользовательского идентификатора полезна, когда Bencher запускается несколько раз на одном и том же коммите для той же комбинации Проекта, Ветки, Тестовой среды и Адаптера, чтобы у каждого запуска была своя строка. Например, запуск по `push` и запуск по `pull_request` в одной ветке используют один и тот же head-коммит, поэтому задайте каждому запуску свой идентификатор или не используйте `--github-actions` для запуска по `push`. Иначе запуски используют одну строку, которая показывает только один из них, а более старый запуск ничего не пишет, как только строку занимает более новый запуск. Идентификатор также используется вместо имени Проекта в имени проверки GitHub (например, `Bencher Report (<ID>)`), поэтому каждый запуск получает стабильное имя, которое можно использовать как отдельную обязательную проверку статуса. Требуется: `--github-actions`
