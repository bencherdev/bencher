### `plus.registry`

Этот раздел определяет конфигурацию хранилища реестра OCI (Open Container Initiative).
Bencher может функционировать как OCI-совместимый реестр контейнеров/артефактов.

Если этот раздел не настроен, Bencher будет использовать локальное файловое хранилище
в директории `registry` рядом с файлом базы данных.
Это подходит для разработки и развёртываний с одним экземпляром.

Для производственных развёртываний с несколькими экземплярами или для надёжности
настройте S3-совместимое хранилище.

Доступны два `scheme` хранилища:
- `file`: Хранение OCI-артефактов в локальной файловой системе (по умолчанию)
    - `path`: (Опционально) Директория для данных реестра. По умолчанию директория `registry` рядом с файлом базы данных.
- `s3`: Хранение OCI-артефактов в любом совместимом S3 хранилище
    - `bucket`: Имя bucket
    - `path`: (Опционально) Префикс ключа в bucket. Ведущие, завершающие и повторяющиеся слеши удаляются, поэтому `registry`, `registry/` и `/registry` сохраняют всё под `registry`.
    - `endpoint`: (AWS: Опционально | Не AWS: Обязательно) Конечная точка хранилища
    - `region`: (Опционально) Регион bucket. Обязателен для AWS. По умолчанию `auto`, что ожидают S3-совместимые хранилища.
    - `access_key_id`: Ключ доступа S3
    - `secret_access_key`: Секретный ключ доступа S3
    - `chunk_size`: (Опционально) Минимальный размер фрагмента в байтах для буферизации данных загрузки перед сохранением. По умолчанию: 5 МБ.
      Тела HTTP-запросов поступают в виде маленьких сетевых фреймов (обычно от 8 до 64 КБ). Без буферизации каждый фрейм становится отдельным объектом, создавая тысячи объектов на каждый слой. Это значение также соответствует минимальному размеру части для многочастной загрузки S3.

Задайте правило жизненного цикла bucket, которое прерывает незавершённые многочастные загрузки. Сбой в середине завершения загрузки блоба оставляет такую загрузку, и сервер её не прерывает.

Если ранее вы настроили `path`, начинающийся или заканчивающийся слешем, перенесите существующие объекты на нормализованный префикс перед обновлением. `path` вида `registry/` сохранял ключи под `registry//<project>/...`, а теперь сохраняет их под `registry/<project>/...`. Каждый сегмент `path` также кодируется процентами в сохранённом ключе, если он содержит управляющий символ ASCII, символ вне ASCII или один из `\` `{` `^` `}` `%` `` ` `` `]` `"` `>` `[` `~` `<` `#` `|` `*` `?`, а сегмент, равный ровно `.` или `..`, сохраняется как `%2E` или `%2E%2E`. Все остальные символы, включая пробелы, `+`, `=`, `@` и `:`, сохраняются как есть, поэтому `team#1` становится `team%231`, а `team+1` остаётся `team+1`. Данные, сохранённые под префиксом, который теперь кодируется, требуют того же переноса. Перед переносом любых данных выведите список ключей, фактически сохранённых в бакете, и сравните их с новым префиксом.

|      Имя       |                 Пример                 | По умолчанию | Обязательно |                   Описание                    |
| :------------: | :------------------------------------: | :----------: | :---------: | :-------------------------------------------: |
|      url       | "https://registry.bencher.example.com" | "http://localhost:6610" |     Нет     | Внешне доступный URL API-сервера для доступа к OCI-реестру. |
|    storage     |               \{ ... \}                |     ---      |     Нет     | Указывает бэкенд хранилища реестра. Локальные файлы, если не указан. |
| storage.scheme |                 "s3"                   |     ---      |     Да      | Указывает `scheme` хранилища. Все остальные ключи `storage` смотрите в списке выше. |
| upload_timeout |                  3600                  |     3600     |     Нет     | Тайм-аут сессии загрузки в секундах. Устаревшие загрузки очищаются при запуске новых загрузок. |
| max_body_size  |               1073741824               |  1073741824  |     Нет     | Максимальный размер тела в байтах для загрузки блобов и манифестов. Запросы, превышающие этот лимит, отклоняются с ошибкой 413 Payload Too Large. По умолчанию: 1 ГиБ. |
