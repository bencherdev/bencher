### `--ci-id <ID>`

<br />

可选：用于将结果发布到 CI 的自定义 ID。
拉取请求上同一项目的所有作业共享一条评论，每个作业各有一行报告。
设置 ID 后，该行的标签为其编号和 ID（例如：`2 (microbench)`）。
在作业的报告存在之前，该行只显示 ID 而没有编号（例如：`(microbench)`），作业运行期间显示为 `Pending`，并排在已编号的行之后。
未设置 ID 时，标签只有编号，并且该行会在作业的报告存在后出现。
默认情况下，以下组合相同的作业共享一行：分支、测试平台和[适配器](/zh/docs/explanation/adapters/)，
如果设置了 [`--build-time`](#--build-time) 和 [`--file-size`](#--file-size-file)，也会包含在内。
当 Bencher 在同一个提交上针对相同的项目、分支、测试平台和适配器组合运行多次时，设置自定义 ID 会很有用，
这样每次运行都会有自己的行。
例如，同一分支上的 `push` 运行和 `pull_request` 运行共享头提交，
因此请为每次运行设置各自的 ID，或者不要在 `push` 运行中使用 `--github-actions`。
否则，这些运行共享一行，该行只显示其中一个，并且一旦较新的运行占据该行，较旧的运行就不会写入任何内容。
该 ID 还会在 GitHub 检查名称中代替项目名称使用（即 `Bencher Report (<ID>)`），
因此每次调用都会获得一个稳定的名称，可以用作单独的必需状态检查。
要求：`--github-actions`
