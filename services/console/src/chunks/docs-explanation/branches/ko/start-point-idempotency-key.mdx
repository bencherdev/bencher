
### `--start-point-idempotency-key <KEY>`

<br />

지정된 키를 [`--start-point-reset` 플래그][start point reset option]의 멱등성 키로 사용합니다.
키는 어떤 텍스트든 될 수 있습니다.
`--start-point-idempotency-key` 옵션 또는 `BENCHER_START_POINT_IDEMPOTENCY_KEY` 환경 변수 중 하나를 설정하세요.
`--start-point-reset`이 설정되지 않았거나 키가 비어 있으면 이 옵션은 무시됩니다.

- 키를 가진 `branch` [Head][head]가 없으면, 재설정은 키를 가진 새로운 `branch` Head를 생성합니다.
- 키를 가진 `branch` Head가 이미 있으면, 해당 Head가 사용되며 `branch`는 다시 재설정되지 않습니다.
  시작 지점이 변경되었거나 해당 Head가 이후에 교체된 경우에도 마찬가지입니다.

GitHub Actions에서 실행할 때, 키의 기본값은 현재 워크플로 실행 시도입니다.
워크플로 실행의 모든 작업은 하나의 `branch` Head를 공유하며, 워크플로를 다시 실행하면 새로운 Head가 생성됩니다.
같은 워크플로 실행에서 이후에 `branch`를 재설정하는 단계도 같은 Head를 사용하므로, `branch`를 다시 재설정해야 하는 단계에는 다른 키를 설정하세요.
다른 CI 제공자의 경우, 파이프라인 실행의 모든 작업에서 동일한 값으로 키를 설정하세요
(예: GitLab CI/CD에서 `--start-point-idempotency-key "$CI_PIPELINE_ID"`).

예를 들어, 워크플로가 각각 `--branch feature_branch --start-point main --start-point-reset --start-point-idempotency-key run-abc123`를 사용하는 세 개의 작업으로 구성된 매트릭스를 실행하는 경우:

1. 가장 먼저 보고하는 작업이 `main`에서 멱등성 키 `run-abc123`를 가진 새로운 `feature_branch` [Head][head]를 생성합니다.
2. 해당 Head가 멱등성 키 `run-abc123`를 가지고 있으므로, 나머지 두 작업은 동일한 `feature_branch` Head를 사용합니다.
3. 세 작업의 결과가 모두 `feature_branch`에 함께 표시됩니다.
