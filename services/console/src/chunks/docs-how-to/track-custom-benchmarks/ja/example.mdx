この例では、キー `benchmark_name` は[ベンチマーク][benchmark]の名前になります。
ベンチマークは、名前、スラッグ、または UUID で識別できます。
`benchmark_name` キーはエントリのリストに対応し、
各エントリは `measures` オブジェクトを持ちます。
`measures` オブジェクトは、複数の[メジャー][measure]の名前、スラッグ、または UUID をキーとして含めることができます。
指定された値が名前またはスラッグで、そのメジャーがまだ存在しない場合は、自動的に作成されます。
ただし、指定された値が UUID の場合は、そのメジャーが既に存在している必要があります。
この例では、`latency` は組み込みの Latency メジャーのスラッグです。
各プロジェクトにはデフォルトで Latency（`latency`）と Throughput（`throughput`）のメジャーがあり、
それぞれ `nanosecond (ns)` と `operations / second (ops/s)` で測定されます。
各メジャーオブジェクトは、[メトリック][metric]の名前をその値に対応させます。
ベンチマークハーネスがメジャーに対して単一の結果を報告する場合は、
そのメトリックに `value` という名前を付けてください。

この例では、`latency` メジャーオブジェクトは `88.0` の `value` メトリックを含みます。

エントリは、`{"size": 64}` のような `parameters` オブジェクトを持つこともできます。
[パラメータ][parameters]の各組はそのベンチマークの1つの[バリアント][variant]になるため、
1つのベンチマークは複数のバリアントを持つことができます。
`parameters` のないエントリは、パラメータのないそのベンチマークのバリアントです。
