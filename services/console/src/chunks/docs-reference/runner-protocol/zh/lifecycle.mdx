## Job 生命周期

每个 Job 在被认领、执行和处理时，会经过一组固定的状态。

| 从        | 到          | 触发条件                                                               |
| --------- | ----------- | ---------------------------------------------------------------------- |
| pending   | claimed     | Runner 认领该 Job                                                 |
| pending   | canceled    | 用户取消该 Job                                                  |
| claimed   | running     | Runner 发送 `running`                                              |
| claimed   | failed      | Runner 发送 `failed`                                                     |
| claimed   | unknown     | 服务器与 Runner 失去联系                                                       |
| claimed   | canceled    | 用户取消该 Job                                                  |
| running   | completed   | Runner 发送 `completed`                                            |
| running   | failed      | Runner 发送 `failed`                                                     |
| running   | unknown     | 服务器与 Runner 失去联系                                                       |
| running   | canceled    | 用户取消该 Job，或超过了硬性 Job 超时             |
| unknown   | completed   | Runner 发送 `completed`                                                  |
| unknown   | failed      | Runner 发送 `failed`                                                     |
| unknown   | canceled    | 用户取消该 Job，或超过了硬性 Job 超时                                                |
| completed | processed   | 服务器成功处理结果                          |
| completed | failed      | 服务器处理结果失败                                                              |
| completed | unknown     | 启动时，服务器发现已存储的结果丢失                                                      |
| failed    | completed   | Runner 重新发送 `completed`，覆盖 `failed` 状态                                 |

`processed` 和 `canceled` 是终止状态。
`completed` 和 `failed` 是准终止状态：
`completed` 在结果被解析后转换为 `processed`，
而 `failed` 在 Runner 重新发送 `completed` 时转换为 `completed`。
`unknown` 表示服务器已与 Runner 失去联系，尚不知道结果。
当 Runner 再次通信时，它会以 Runner 发送的结果解决；
当 Job 的截止时间过去时，它会以 `canceled` 解决。
每次转换在其数据库更新上都使用状态过滤器，
因此被并发修改的 Job 会被重新读取而不是被覆盖。
