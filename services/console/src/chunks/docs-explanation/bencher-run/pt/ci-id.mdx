### `--ci-id <ID>`

<br />

Opcional: ID personalizado para publicar resultados no CI.  
Todos os trabalhos de um Projeto em um pull request compartilham um único comentário, e o ID nomeia a seção do trabalho nesse comentário.  
Com um ID, a seção do trabalho aparece como `Pending` enquanto o trabalho é executado.  
Sem um ID, a seção aparece assim que o Relatório do trabalho é criado.  
Por padrão, a seção de um trabalho é nomeada pela combinação de: Branch, Ambiente de Teste e [Adaptador](/pt/docs/explanation/adapters/),  
junto com [`--build-time`](#--build-time) e [`--file-size`](#--file-size-file), se definidos.  
Definir um ID personalizado é útil quando o Bencher está sendo executado várias vezes no mesmo commit para a mesma combinação de Projeto, Branch, Ambiente de Teste e Adaptador,  
para que cada execução tenha sua própria seção.  
Por exemplo, uma execução de `push` e uma execução de `pull_request` no mesmo branch compartilham o commit head,  
então dê a cada execução seu próprio ID, ou não use `--github-actions` na execução de `push`.  
Caso contrário, apenas a seção do trabalho mais recente pode aparecer, e o outro trabalho não escreve nada.  
O ID também é usado no lugar do nome do Projeto no nome da Verificação do GitHub (ou seja, `Bencher Report (<ID>)`),  
de modo que cada invocação recebe um nome estável que pode ser usado como uma verificação de status obrigatória separada.  
Requer: `--github-actions`
