## #️⃣ C# DotNet

Адаптер C# DotNet (`c_sharp_dot_net`) ожидает вывод [BenchmarkDotNet](https://github.com/dotnet/BenchmarkDotNet) в [формате JSON (то есть `--exporters json`)](https://benchmarkdotnet.org/articles/configs/exporters.html#sample-introexportjson).
Читаются как краткий (brief), так и полный (full) JSON-экспорт.
Этот JSON-вывод сохраняется в файл, поэтому вы должны использовать опцию `--file` команды CLI `bencher run`, чтобы указать путь к этому файлу.
BenchmarkDotNet называет этот файл по классу бенчмарка и его пространству имен, поэтому замените `Benchmarks` полным именем вашего класса.

<Dotnet />

Имя Бенчмарка является полным именем до его аргументов (то есть `Namespace.Type.Method`), а вложенный тип сохраняет свой `+` (то есть `Namespace.Outer+Type.Method`).
Каждое значение `[Params]` и `[Arguments]` становится Параметром в виде строки, как его печатает BenchmarkDotNet.
Задание (job) становится Параметром `@job` со своим Id в том виде, в каком его показывает сводка BenchmarkDotNet (то есть `DefaultJob` или `ShortRun`),
а задание, в котором указана среда выполнения, добавляет Параметр `@runtime`.
Случай, который BenchmarkDotNet печатает так же, как уже прочитанный, учитывается как пропущенный в замечаниях Отчета.

Измерение `latency` собирается в наносекундах (ns) со всеми статистиками, которые сообщает BenchmarkDotNet:
`mean`, `median`, `min`, `max`, `std_dev`, `std_err`, `p25`, `p75`, `iqr`, `lower_fence`, `upper_fence`,
перцентилями (то есть `p67`, `p80`, `p85`, `p90` и `p95`)
и интервалом среднего с его уровнем (то есть `mean_ci99_9_lower`, `mean_ci99_9_upper` и `mean_ci99_9_margin`).
С диагностикой памяти (memory diagnoser) также собираются Измерение `allocated` (байт на операцию)
и Измерения `gen0-collects-per-1000-ops`, `gen1-collects-per-1000-ops` и `gen2-collects-per-1000-ops`, каждое как `mean`.
Каждая другая метрика полного экспорта, например метрика диагностики, является Измерением, названным по ее идентификатору, как `value`.

В первую очередь задайте Порог для Метрики `median` у `latency` с помощью `--threshold-metric median`, для `mean` у Измерений памяти и для `value` у других метрик полного экспорта.

BenchmarkDotNet ничего не экранирует в своем выводе, поэтому несколько случаев читаются неточно:
значение, содержащее `&Name=`, читается как два Параметра,
длинное значение обрезается так, как его показывает BenchmarkDotNet (то есть `head(...)tail [len]`),
а строка, содержащая `, Runtime=`, может быть прочитана как `@runtime`.
До BenchmarkDotNet 0.15.2 задание без Id получает случайный Id при каждом запуске,
поэтому каждый раз начинаются новые Варианты: задайте заданию Id с помощью `WithId`.

<summary>BMF версия 0</summary>

В BMF версии 0 имя Бенчмарка имеет вид `Namespace.Method`, и собирается Измерение `latency` (то есть `nanoseconds (ns)`).
С диагностикой памяти также собираются Измерения `allocated`, `gen0-collects`, `gen1-collects`, `gen2-collects` и `total-operations`, каждое как `value`.
Для Метрики `latency` есть два варианта:
- `mean` (по умолчанию): `lower_value` и `upper_value` находятся на одно стандартное отклонение ниже и выше среднего (то есть `value`) соответственно.
- `median`: `lower_value` и `upper_value` находятся на один межквартильный размах ниже и выше медианы (то есть `value`) соответственно.

Это можно указать в подкоманде CLI <code><a href="/ru/docs/explanation/bencher-run/">bencher run</a></code> с помощью опции `--average`.

</details>
