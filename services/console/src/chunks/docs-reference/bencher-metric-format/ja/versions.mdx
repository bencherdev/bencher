## BMF Versions

すべてのプロジェクトは BMF のバージョンを持ち、新しいプロジェクトはバージョン 1 で開始します。
レポートは、その `bmf_version` フィールドで宣言されたバージョンで読み取られ、宣言がない場合はそのプロジェクトのバージョンで読み取られます。
<code><a href="/ja/docs/explanation/bencher-run/">bencher run</a></code> CLI サブコマンドは、プロジェクトのバージョンを読み取り、すべてのレポートでそれを宣言します。
まだ存在しないプロジェクトは、実行によってバージョン 1 で作成されるため、バージョン 1 として読み取られます。

宣言されたバージョンは契約です。
もう一方のバージョンでパースされる結果は `400 Bad Request` を受け取ります。
このエラーは両方のバージョンを示し、期待されるバージョンがどこから来たのかを伝え、修正方法を一覧表示します。

[`json` アダプター][json adapter]は、レポートのバージョンで JSON を読み取ります。
`json_v0` アダプターと `json_v1` アダプターは、それぞれ独自のバージョンで JSON を読み取り、
`bencher run --adapter json_v0` または `--adapter json_v1` は、どのプロジェクトでもそのバージョンを宣言します。

プロジェクトを編集できるユーザーは、
`bencher project update --bmf-version 1`、API、またはプロジェクト設定の Move to version 1 ボタンで、プロジェクトをバージョン 0 からバージョン 1 に移行できます。
プロジェクトをバージョン 0 に戻せるのはサーバー管理者のみです。

<summary>BMF バージョン 0</summary>

BMF バージョン 0 は以前のバージョンで、バージョン 0 のプロジェクトで引き続き使用されています。
各ベンチマーク名をそのメジャーに対応付け、各メジャーをメトリックのトリプルに対応付けます：

<BmfV0Example />

バージョン 0 では、ベンチマークはパラメータを持たないため、バリアントは1つです。
メジャーは、必須の `value` と、オプションの `lower_value` および `upper_value` を持ちます。
バージョン 0 はこれら3つの名前のみを読み取ります。メジャー内のその他の名前は、警告なしで無視されます。
