Se você está usando o Bencher Cloud, então você pode simplesmente [se registrar](/auth/signup) ou [entrar](/auth/login)
usando o botão `GitHub`.

Para o Bencher Self-Hosted, você precisará ter um [plano Bencher Plus Enterprise][bencher plus enterprise], criar seu próprio GitHub App e atualizar sua [configuração do console][console config] e [configuração do servidor API][server config].

[bencher plus enterprise]: /pricing/?level=enterprise
[console config]: /pt/docs/reference/console-config/
[server config]: /pt/docs/reference/server-config/

## Criar um apllicativo GitHub

- Crie um [aplicativo GitHub](https://docs.github.com/pt/apps/creating-github-apps/registering-a-github-app/registering-a-github-app#registering-a-github-app)
- Nome do aplicativo GitHub
  - Escolha um nome único (ex: `Bencher para a Minha Empresa`)
- URL da página inicial
  - Defina-o para sua URL do Console Bencher Self-Hosted (ex: `https://bencher.example.com`)
- Identificando e autorizando usuários
  - URL de callback
    - Defina o URL de callback para sua URL do Console Bencher Self-Hosted com o caminho `/auth/github` (ex: `https://bencher.example.com/auth/github`)
  - ✅ Expirar tokens de autorização de usuário
  - ✅ Solicitar autorização do usuário (OAuth) durante a instalação
  - ✅ Ativar Fluxo de Dispositivo
- Webhook
  - ❌ Ativo - Desmarque esta caixa
- Permissões
  - Permissões da conta
    - Endereços de e-mail: `Somente leitura`
- Onde este aplicativo GitHub pode ser instalado?
  - 🔘 Qualquer conta
- Clique `Criar aplicativo GitHub`
- Agora em `Geral` para o aplicativo recém-criado
- Anote o `ID do Cliente` (ex: `Iv1.12864abcd1232048`)
- Segredos do cliente
  - Clique `Gerar um novo segredo de cliente`
  - Anote este segredo (ex: `00000abcd12345wxyz123456789abcdefgh0000`)
- Adicione o [logo PNG do Bencher](/brand/) em Informações de exibição
- Chaves privadas
  - Clique `Gerar uma chave privada`

## Configuração do aplicativo GitHub

### Interface do usuário do console
Defina a variável de ambiente `GITHUB_CLIENT_ID` quando você executar a imagem Docker do `bencher-console`. (ex: `GITHUB_CLIENT_ID=Iv1.12864abcd1232048`) Se o ID do cliente estiver faltando, então os botões do GitHub não aparecerão na UI.

### Servidor API
Adicione o `client_id` e o `client_secret` à [seção `plus.github` da configuração do servidor](/pt/docs/reference/server-config/#plusgithub). Se a seção GitHub estiver faltando, então o servidor falhará em qualquer solicitação de autenticação do GitHub.

## Repositórios vinculados

Estas configurações exigem o servidor API e o Console do Bencher Self-Hosted em `v0.6.18` ou posterior.

Para que um Projeto possa [vincular um repositório GitHub][linked repository] para suas execuções desanexadas,
defina também estas configurações para o aplicativo GitHub:

- Identificando e autorizando usuários
  - URL de callback
    - Defina o primeiro URL de callback para sua URL do Console Bencher Self-Hosted com o caminho `/console/github` (ex: `https://bencher.example.com/console/github`).
      O GitHub envia o usuário para o primeiro URL de callback depois que ele instala o aplicativo.
    - Mantenha depois dele o URL de callback com o caminho `/auth/github`, para o login (ex: `https://bencher.example.com/auth/github`).
      O GitHub recusa um login cujo URL de callback não esteja na lista.
  - ✅ Solicitar autorização do usuário (OAuth) durante a instalação
- Webhook
  - ✅ Ativo - Marque esta caixa
  - URL do webhook
    - Defina-o para sua URL do Servidor API Bencher Self-Hosted com o caminho `/v0/github/webhook` (ex: `https://api.bencher.example.com/v0/github/webhook`)
  - Segredo do webhook
    - Insira um segredo aleatório e anote-o (ex: `0123456789abcdef0123456789abcdef`)
- Permissões
  - Permissões do repositório
    - Checks: `Leitura e escrita`
    - Conteúdo: `Somente leitura`
    - Pull requests: `Leitura e escrita`
  - Inscrever-se em eventos
    - Deixe todos os eventos desmarcados
- Anote o slug do aplicativo, a última parte da URL de sua página pública (ex: `my-bencher-app` em `https://github.com/apps/my-bencher-app`)

Adicione o slug, a chave privada e o segredo do webhook como `app` à [seção `plus.github` da configuração do servidor](/pt/docs/reference/server-config/#plusgithub).

Para atualizar um aplicativo que uma versão anterior configurou com Conteúdo: `Leitura e escrita`:

1. Adicione Checks e Pull requests antes da atualização.
   O GitHub pede ao proprietário de cada instalação que os aprove.
2. Atualize o servidor API e o Console para `v0.6.18` ou posterior.
   Depois da atualização, um repositório cuja instalação não aprovou as novas permissões não pode ser vinculado, e o Bencher não pode publicar nele.
3. Altere Conteúdo para `Somente leitura`, como uma alteração separada.

## GitHub Enterprise Server

Para usar o GitHub Enterprise Server no lugar do github.com, registre o aplicativo GitHub no seu GitHub Enterprise Server com as configurações acima.
Depois defina `server_url` na [seção `plus.github` da configuração do servidor](/pt/docs/reference/server-config/#plusgithub) como sua raiz web (ex: `https://github.example.com`).
O Bencher então o usa para o login, os repositórios vinculados, os títulos dos commits e os GitHub Checks e comentários de pull request das execuções desanexadas.
O slug do aplicativo é a última parte da URL de sua página pública (ex: `my-bencher-app` em `https://github.example.com/github-apps/my-bencher-app`).

Isso requer o servidor de API do Bencher Self-Hosted na `v0.6.18` ou posterior,
e uma licença válida do Bencher Plus Enterprise para pelo menos uma organização no servidor.
Sem a licença, o Bencher recusa o login com GitHub, a vinculação e as execuções desanexadas no GitHub Actions, e não busca títulos de commits.
O Bencher publica para uma execução desanexada somente quando seu workflow roda no mesmo GitHub Enterprise Server:
ele recusa uma execução cujo `GITHUB_API_URL` é a API de qualquer outro GitHub.
