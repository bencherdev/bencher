### Лог-нормальное распределение

Тест на лог-нормальное распределение (`log_normal`) измеряет, насколько вероятно, что новая метрика выше или ниже центрального положения ваших исторических метрик, используя [лог-нормальное распределение](https://ru.wikipedia.org/wiki/%D0%9B%D0%BE%D0%B3%D0%BD%D0%BE%D1%80%D0%BC%D0%B0%D0%BB%D1%8C%D0%BD%D0%BE%D0%B5_%D1%80%D0%B0%D1%81%D0%BF%D1%80%D0%B5%D0%B4%D0%B5%D0%BB%D0%B5%D0%BD%D0%B8%D0%B5).

Тесты на лог-нормальное распределение лучше всего работают, когда:
- Запуски эталонов полностью независимы друг от друга
- Количество итераций для одного запуска эталона составляет менее 10% от исторических метрик
- Все данные положительные (натуральный логарифм отрицательного числа `неопределен`)

Для тестов на лог-нормальное распределение вероятность выражается в виде десятичного процента.
Если новая метрика ниже определенного процентного значения слева (нижняя граница)
или выше определенного процентного значения справа (верхняя граница) для ваших исторических метрик, генерируется предупреждение.
Должна быть установлена либо нижняя граница, верхняя граница, либо обе.

- #### Нижняя граница лог-нормального распределения
  - Нижняя граница теста на лог-нормальное распределение может быть любым положительным десятичным значением между `0.5` и `1.0`.
Где `0.5` представляет центральное положение, а `1.0` — все возможные значения слева (-∞).
Она используется, когда меньшее значение будет указывать на ухудшение производительности.
  - Например, если вы использовали тест на лог-нормальное распределение с нижней границей `0.977`,
и у вас было `25` исторических метрик, сосредоточенных вокруг `100`, и один предыдущий выброс на `200`,
граница нижнего предела составила бы `71.20`, и
любое значение меньше `71.20` вызовет предупреждение.
- #### Верхняя граница лог-нормального распределения
  - Верхняя граница теста на лог-нормальное распределение может быть любым положительным десятичным значением между `0.5` и `1.0`.
Где `0.5` представляет центральное положение, а `1.0` — все возможные значения справа (∞).
Она используется, когда большее значение будет указывать на ухудшение производительности.
  - Например, если вы использовали тест на лог-нормальное распределение с верхней границей `0.977`,
и у вас было `25` исторических метрик, сосредоточенных вокруг `100`, и один предыдущий выброс на `200`,
граница верхнего предела составила бы `134.18`, и
любое значение больше `134.18` вызовет предупреждение.
- #### Границы лог-нормального распределения для всего Отчета
  - Для Проекта с версией BMF 1 граница лог-нормального распределения охватывает весь Отчет.
Верхняя Граница `0.99` означает, что Отчет без изменений вызывает Оповещение Верхней Границы не чаще 1 раза из 100, сколько бы Линий в нем ни было.
Bencher делит эту вероятность поровну между всеми проверками на этой стороне Отчета: каждый Порог, на каждой Линии, которую он проверяет, в каждой итерации.
Линия, у которой слишком мало исторических Метрик для проверки, все равно получает свою долю.
  - Например, Отчет с `200` Линиями и Верхней Границей `0.99` проверяет каждую Линию на уровне `0.99995`.
Для нормального распределения это сдвигает лимит Верхней Границы каждой Линии примерно с `2.33` до примерно `3.89` стандартных отклонений выше среднего.
  - Для Проекта с версией BMF 0 граница лог-нормального распределения охватывает каждую Линию отдельно.
Отчет с `200` Линиями и Верхней Границей `0.99` вызывает около `2` ложных Оповещений Верхней Границы.
  - При короткой истории тест на лог-нормальное распределение занижает разброс ваших исторических Метрик,
поэтому его реальная вероятность ложного Оповещения выше заявленной, как для одной Линии, так и для всего Отчета.
