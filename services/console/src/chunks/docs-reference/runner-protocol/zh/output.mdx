## Job 输出

当 Runner 发送 `completed` 或 `failed` 时，
该次执行的输出会立即存储在与容器 Image 相同的 OCI 存储后端中，
路径为 `{project}/output/v0/executions/{execution}`。
当 Job 的每次迭代都有了结果时，
服务器会按迭代顺序由各次执行组装出 Job 的输出，
并将其存储在路径 `{project}/output/v0/jobs/{job}`。

存储的输出包含一个按迭代划分的 `results` 数组，并在失败时包含一个 `error` 字符串。
每次迭代都记录其 `exit_code`、`stdout`、`stderr`，
以及任何收集到的输出文件到其内容的映射。
在 `allow_failure` 下，运行失败的迭代只保留其 `exit_code` 和 `stderr`，
因此它保留自己的位置，且其中的 Metric 不会进入 Report。
在输出被存储后，服务器对结果运行 [基准测试工具适配器][adapters]，
将 Metric 和 Alert 解析到 Report 中，并将 Job 转换为 `processed`。

当使用 [`GET /v0/projects/{project}/jobs/{job}` API][job query api] 查询 Job 时会返回该输出。
约束 WebSocket 消息的同一个 `request_body_max_bytes` 限制
也限定了 Runner 可以交付的输出大小。
