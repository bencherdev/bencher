## 🕸 JavaScript Vitest

JavaScript Vitest 适配器（`js_vitest`）接受 JSON 格式的 [Vitest `bench`](https://vitest.dev/api/#bench) 输出。
此 JSON 输出保存在文件中，因此您必须使用 `bencher run` CLI 的 `--file` 选项来指定该文件路径。
对于 Vitest 5 及更高版本，请使用 JSON 报告器（即 `--reporter=json --outputFile=results.json`）：

每个基准测试的名称由以下部分用 ` > ` 连接而成：其文件（相对于 JSON 输出中所有文件的共同目录），
然后是其 `describe` 块、测试、分组（不是默认分组时）和任务。
例如 `sub/sort.bench.ts > sorting > arrays > normal`。
只运行部分基准测试文件可能会改变该共同目录，从而重命名基准测试。
没有参数。

`latency` 度量（即 `nanoseconds (ns)`）和 `throughput` 度量（即 `operations / second (ops/s)`）都以下列指标收集：
- `mean`、`median`、`min` 和 `max`
- `p75`、`p99`、`p99_5` 和 `p99_9`：第 75、99、99.5 和 99.9 百分位数
- `std_dev`、`std_err`、`median_abs_dev` 和 `mean_abs_dev`：标准差、平均值的标准误差，以及中位数绝对偏差和平均绝对偏差
- `mean_ci95_lower`、`mean_ci95_upper` 和 `mean_ci95_margin`：平均值的 95% 置信区间及其误差范围

对于 Vitest 1 至 4，`latency` 度量包含 JSON 输出中的统计量，
`throughput` 度量包含其 `mean` 以及 `mean_ci95_lower` 和 `mean_ci95_upper`。
请首先为 `median` 指标设置阈值，使用 `--threshold-metric median`。
在没有 `median` 的情况下（例如 Vitest 1 至 4 的 `throughput` 和 Vitest 1 的 `latency`），请首先为 `mean` 设置阈值。

当两个 Vitest 项目运行同一个文件时，Vitest 5 的 JSON 输出会在同一路径下包含该文件两次。
保留第一份，每次重复都会在报告的警告中计为已跳过。
要只运行一个项目，请向 Vitest 传递 `--project`。

<summary>BMF 版本 0</summary>

只读取 Vitest 1 至 4 的 `--outputJson` 格式。
对于 `throughput` 度量，`lower_value` 和 `upper_value` 分别是低于和高于 `value` 的相对误差范围。

`latency` 指标有两个选项：
- `mean`（默认）：`lower_value` 和 `upper_value` 分别是低于和高于平均值（即 `value`）一个标准差。
- `median`：只有中位数（即 `value`）可用。由于 Vitest 不提供四分位距，`lower_value` 和 `upper_value` 都不会被收集。

这可以在 <code><a href="/zh/docs/explanation/bencher-run/">bencher run</a></code> CLI 子命令中通过 `--average` 选项指定。
