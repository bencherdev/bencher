## 🕸 JavaScript Vitest

The JavaScript Vitest Adapter (`js_vitest`) expects [Vitest `bench`](https://vitest.dev/api/#bench) output in JSON format.
This JSON output is saved to a file, so you must use the `bencher run` CLI `--file` option to specify that file path.
For Vitest 5 and later, use the JSON reporter (ie `--reporter=json --outputFile=results.json`):

For Vitest 1 to 4, use `--outputJson results.json`:

Each Benchmark is named by its file, relative to the common directory of every file in the report,
then its `describe` blocks, its test, its group (when it is not the default), and its task, joined with ` > `.
For example, `sub/sort.bench.ts > sorting > arrays > normal`.
Running only some of your benchmark files can change that common directory, which renames the Benchmarks.
There are no Parameters.

Both the `latency` Measure (ie `nanoseconds (ns)`) and the `throughput` Measure (ie `operations / second (ops/s)`) are gathered with these Metrics:
- `mean`, `median`, `min`, and `max`
- `p75`, `p99`, `p99_5`, and `p99_9`: the 75th, 99th, 99.5th, and 99.9th percentiles
- `std_dev`, `std_err`, `median_abs_dev`, and `mean_abs_dev`: the standard deviation, the standard error of the mean, and the median and mean absolute deviations
- `mean_ci95_lower`, `mean_ci95_upper`, and `mean_ci95_margin`: the mean's 95% confidence interval and its margin of error

For Vitest 1 to 4, the `latency` Measure has the statistics its report holds,
and the `throughput` Measure has its `mean` with `mean_ci95_lower` and `mean_ci95_upper`.
Threshold the `median` Metric first, with `--threshold-metric median`.
Where there is no `median`, as in Vitest 1 to 4's `throughput` and Vitest 1's `latency`, threshold the `mean` first.

When two Vitest projects run the same file, the Vitest 5 report holds that file twice under one path.
The first copy is kept, and each repeat is counted as skipped in the Report's warnings.
Pass `--project` to Vitest to run a single project.

Only the Vitest 1 to 4 `--outputJson` format is read.
For the `throughput` Measure, the `lower_value` and `upper_value` are the relative margin of error below and above the `value` respectively.

There are two options for the `latency` Metric:
- `mean` (default): The `lower_value` and `upper_value` are one standard deviation below and above the mean (ie `value`) respectively.
- `median`: Only the median (ie `value`) is available. Neither `lower_value` nor `upper_value` are collected, as Vitest does not provide an interquartile range.

This can be specified in the <code><a href="/docs/explanation/bencher-run/">bencher run</a></code> CLI subcommand with the `--average` option.
