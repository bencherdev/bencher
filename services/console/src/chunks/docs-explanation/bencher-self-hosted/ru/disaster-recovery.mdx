## Восстановление после сбоя

Чтобы предотвратить потерю данных, Bencher предлагает встроенное решение для восстановления после сбоя. Для восстановления после сбоя требуется действующая лицензия [Bencher Plus _Enterprise_][pricing] хотя бы для одной организации на сервере, и сервер с настроенным восстановлением после сбоя без такой лицензии отказывается запускаться. Работающий сервер продолжает репликацию до перезапуска, даже после истечения срока его последней лицензии, а с первого дня льготного периода этой лицензии сервер ежедневно записывает в журнал ошибку, в которой указано, когда он откажется запускаться.

Поддерживаемые схемы репликации:

- `file`: Репликация в локальный путь к файлу
- `s3`: Репликация в любое совместимое с S3 хранилище блобов

Используйте раздел [`plus.disaster_recovery`][plus disaster recovery] конфигурации API-сервера, чтобы настроить восстановление после сбоя для вашего самостоятельно хостируемого API-сервера Bencher.

Чтобы остановить сервер с настроенным восстановлением после сбоя, отправьте сигнал остановки (`SIGTERM` или `SIGINT`) только процессу API-сервера. Затем API-сервер завершает обработку текущих запросов и останавливает репликацию, которая перед завершением реплицирует последние изменения. Второй сигнал остановки, отправленный напрямую процессу репликации (`litestream`), отменяет эту последнюю репликацию, и последние изменения могут быть потеряны. `docker stop` отправляет сигнал остановки только процессу API-сервера. В systemd задайте `KillMode=mixed` в юните, чтобы сигнал остановки получал только процесс API-сервера.
