### `--ci-id <ID>`

<br />

オプション: CIに結果を投稿するためのカスタムID。
プルリクエスト上のプロジェクトのすべてのジョブは1つのコメントを共有し、ジョブごとに1つのレポート行を持ちます。
IDを指定すると、行のラベルはその番号とIDになります（例：`2 (microbench)`）。
ジョブのレポートが存在するまで、その行は番号なしでIDのみを表示し（例：`(microbench)`）、ジョブの実行中は`Pending`となり、番号付きの行の後に置かれます。
IDを指定しない場合、ラベルは番号のみとなり、行はジョブのレポートが存在した時点で表示されます。
デフォルトでは、ブランチ、テストベッド、および[アダプター](/ja/docs/explanation/adapters/)の組み合わせが同じジョブは1つの行を共有し、
設定されている場合は[`--build-time`](#--build-time)と[`--file-size`](#--file-size-file)も加わります。
同じプロジェクト、ブランチ、テストベッド、アダプターの組み合わせで、同じコミットに対してBencherを複数回実行する場合に、
各実行が独自の行を持つようにカスタムIDを設定することが有用です。
たとえば、同じブランチ上の`push`による実行と`pull_request`による実行はヘッドコミットを共有するため、
各実行に独自のIDを指定するか、`push`による実行では`--github-actions`を使用しないでください。
そうしないと、それらの実行は1つの行を共有し、その行にはそのうち1つだけが表示され、新しい実行がその行を占めると、古い実行は何も書き込みません。
このIDはGitHubチェック名でプロジェクト名の代わりに使用されるため（例：`Bencher Report (<ID>)`）、
各実行が個別の必須ステータスチェックとして使用できる安定した名前を持つことになります。
必要条件: `--github-actions`
