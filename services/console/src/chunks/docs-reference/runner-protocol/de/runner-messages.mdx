## Runner-Nachrichten

Nachrichten, die vom Runner an den Server gesendet werden.

| Event       | Beschreibung                                       | Payload                                                                 |
| ----------- | -------------------------------------------------- | ----------------------------------------------------------------------- |
| `ready`     | Der Runner ist im Leerlauf und fordert einen Job an | Optionales `poll_timeout` (1-900s) und `runner`-Metadaten (`os`, `arch`, `version`, optionaler Update-`channel` und optionale Binary-`checksum`) sowie optional die `health` der Festplatten |
| `paused`    | Der Runner ist im Leerlauf, nimmt aber keinen Job an, bis seine Pausengründe entfallen; der Server hält die Abfrage und antwortet mit `no_job` | `reasons` (jeweils mit einem `kind`: `raid` oder `maintenance`), `since` und alle Felder von `ready` |
| `running`   | Job-Setup ist abgeschlossen und der Benchmark startet | Keine                                                                |
| `heartbeat` | Periodisches Lebenszeichen (etwa einmal pro Sekunde) | Keine                                                                   |
| `completed` | Der Benchmark wurde erfolgreich abgeschlossen      | `job` (die UUID der `job`-Nachricht) und `results` (die Ausgabe des Laufs) |
| `failed`    | Der Benchmark ist fehlgeschlagen                   | `job` (die UUID der `job`-Nachricht), `results` und `error`             |
| `canceled`  | Bestätigt eine Abbruchanforderung vom Server       | `job` (die UUID der `job`-Nachricht)                                    |

Die UUID einer `job`-Nachricht benennt diese Ausführung, nicht den Job.
Der Runner gibt sie zurück, sodass ein Ergebnis seine Ausführung genau benennt,
auch wenn es erneut gesendet wird, nachdem eine andere Ausführung desselben Jobs versendet wurde.
