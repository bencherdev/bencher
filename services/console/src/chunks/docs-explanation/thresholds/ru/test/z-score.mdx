### z-score

Тест z-score (`z_score`) измеряет количество [стандартных отклонений](https://en.wikipedia.org/wiki/Standard_deviation) (σ), на которое новая метрика отличается от среднего значения ваших исторических метрик, используя [z-score](https://en.wikipedia.org/wiki/Standard_score).

Тесты z-score работают лучше всего, когда:
- Нет экстремальных различий между эталонными запусками
- Эталонные запуски полностью независимы друг от друга
- Количество итераций для одного эталонного запуска составляет менее 10% от исторических метрик
- Есть как минимум 30 исторических метрик (минимальный размер выборки >= 30)

Для тестов z-score стандартные отклонения выражаются в виде десятичного накопительного процента.
Если новая метрика оказывается ниже определенного левого накопительного процента (нижняя граница) или выше определенного правого накопительного процента (верхняя граница) ваших исторических метрик, генерируется предупреждение.
Должна быть установлена либо нижняя граница, либо верхняя граница, либо обе.

- #### Нижняя граница z-score
  - Нижняя граница теста z-score может быть любым положительным десятичным числом между `0.5` и `1.0`. Где `0.5` представляет среднее значение, а `1.0` — все возможные левые значения (-∞). Она используется, когда меньшее значение указывает на регрессию производительности.
  - Например, если вы использовали тест z-score с нижней границей `0.977` и ваши исторические метрики имели среднее `100` и стандартное отклонение `10`, предел нижней границы составил бы `80.05`, и любое значение менее `80.05` генерировало бы предупреждение.
- #### Верхняя граница z-score
  - Верхняя граница теста z-score может быть любым положительным десятичным числом между `0.5` и `1.0`. Где `0.5` представляет среднее значение, а `1.0` — все возможные правые значения (∞). Она используется, когда большее значение указывает на регрессию производительности.
  - Например, если вы использовали тест z-score с верхней границей `0.977` и ваши исторические метрики имели среднее `100` и стандартное отклонение `10`, предел верхней границы составил бы `119.95`, и любое значение больше `119.95` генерировало бы предупреждение.
- #### Границы z-score для всего Отчета
  - Для Проекта с версией BMF 1 граница z-score охватывает весь Отчет.
Верхняя Граница `0.99` означает, что Отчет без изменений вызывает Оповещение Верхней Границы не чаще 1 раза из 100, сколько бы Линий в нем ни было.
Bencher делит эту вероятность поровну между всеми проверками на этой стороне Отчета: каждый Порог, на каждой Линии, которую он проверяет, в каждой итерации.
Линия, у которой слишком мало исторических Метрик для проверки, все равно получает свою долю.
  - Например, Отчет с `200` Линиями и Верхней Границей `0.99` проверяет каждую Линию на уровне `0.99995`.
Для нормального распределения это сдвигает лимит Верхней Границы каждой Линии примерно с `2.33` до примерно `3.89` стандартных отклонений выше среднего.
  - Для Проекта с версией BMF 0 граница z-score охватывает каждую Линию отдельно.
Отчет с `200` Линиями и Верхней Границей `0.99` вызывает около `2` ложных Оповещений Верхней Границы.
  - При короткой истории z-score занижает разброс ваших исторических Метрик,
поэтому его реальная вероятность ложного Оповещения выше заявленной, как для одной Линии, так и для всего Отчета.
