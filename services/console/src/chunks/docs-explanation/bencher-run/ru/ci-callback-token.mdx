### `--ci-callback-token <TOKEN>`

<br />

Необязательно: Задает токен аутентификации, который использует callback отсоединенного [Job на выделенном оборудовании][job].

При использовании [флага `--detach`][detach] и [опции `--github-actions`](#--github-actions-github_token)
API-сервер Bencher запускает workflow [`repository_dispatch`][github repository dispatch], когда Job завершается.
Для Проекта со [связанным репозиторием][pull requests on bare metal] Bencher создает токен сам, поэтому эта опция не нужна.
Чтобы вместо этого использовать собственный токен, укажите в этой опции [детализированный персональный токен доступа][github fine-grained token]
для репозитория как минимум с разрешением `contents: write`.
Тогда Bencher отправляет событие `repository_dispatch` с этим токеном, есть ли у Проекта связанный репозиторий или нет.
CLI требует эту опцию на GitHub Enterprise Server и с API-сервером Bencher версии ниже `v0.6.14`.
Без нее отсоединенный запуск `claimed` Проекта отклоняется, если у сервера нет приложения GitHub, у Проекта нет связанного репозитория или его связанный репозиторий отключен.
См. [Pull Requests на выделенном оборудовании в GitHub Actions][pull requests on bare metal] для полного обзора.

> 🐰 Здесь нельзя просто использовать `GITHUB_TOKEN`, так как срок его действия истекает сразу после завершения текущего workflow!
