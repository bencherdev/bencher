## Job-Lebenszyklus

Jeder Job durchläuft eine feste Menge von Zuständen, während er beansprucht, ausgeführt und verarbeitet wird.

| Von       | Nach        | Auslöser                                                               |
| --------- | ----------- | ---------------------------------------------------------------------- |
| pending   | claimed     | Ein Runner beansprucht den Job                                         |
| pending   | canceled    | Ein Benutzer bricht den Job ab                                         |
| claimed   | running     | Der Runner sendet `running`                                            |
| claimed   | failed      | Der Runner sendet `failed`                                             |
| claimed   | unknown     | Der Server verliert den Kontakt zum Runner                             |
| claimed   | canceled    | Ein Benutzer bricht den Job ab                                         |
| running   | completed   | Der Runner sendet `completed`                                          |
| running   | failed      | Der Runner sendet `failed`                                             |
| running   | unknown     | Der Server verliert den Kontakt zum Runner                             |
| running   | canceled    | Ein Benutzer bricht den Job ab, oder das harte Job-Timeout wird überschritten |
| unknown   | completed   | Der Runner sendet `completed`                                          |
| unknown   | failed      | Der Runner sendet `failed`                                             |
| unknown   | canceled    | Ein Benutzer bricht den Job ab, oder das harte Job-Timeout wird überschritten |
| completed | processed   | Der Server verarbeitet die Ergebnisse erfolgreich                      |
| completed | failed      | Der Server kann die Ergebnisse nicht verarbeiten                       |
| completed | unknown     | Beim Start stellt der Server fest, dass die gespeicherten Ergebnisse verloren gingen |

`processed`, `failed` und `canceled` sind terminal: Ein `failed`- oder `canceled`-Job ändert seinen Zustand nie wieder.
`completed` ist quasi-terminal:
`completed` geht in `processed` über, sobald die Ergebnisse geparst sind, in `failed`, wenn sie nicht verarbeitet werden können, oder in `unknown`, wenn der Server beim Start feststellt, dass sie verloren gingen.
`unknown` bedeutet, dass der Server den Kontakt zum Runner verloren hat und das Ergebnis noch nicht kennt.
Der Zustand löst sich auf, sobald sich der Runner wieder meldet, mit dem Ergebnis, das er sendet,
oder als `canceled`, sobald die Frist des Jobs abläuft.
Jeder Übergang verwendet einen Statusfilter bei seinem Datenbank-Update,
sodass ein Job, der gleichzeitig geändert wurde, neu eingelesen statt überschrieben wird.
