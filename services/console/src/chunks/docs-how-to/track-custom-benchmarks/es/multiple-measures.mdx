## Múltiples Medidas

En [Bencher Metric Format (BMF) JSON][bmf]
el objeto `measures` de una entrada de [Benchmark][benchmark] puede contener múltiples nombres, slugs o UUIDs de [Medida][measure] como claves.
Si el valor especificado es un nombre o slug y la Medida no existe ya, se creará para ti.
Sin embargo, si el valor especificado es un UUID, entonces la Medida debe existir ya.
Cada objeto de Medida asocia nombres de [Métrica][metric] con sus valores.

En este ejemplo, el objeto de Medida `latency` contiene una Métrica `value` de `88.0`,
y el objeto de Medida `throughput` contiene una Métrica `value` de `5.55`.

Puedes usar [el subcomando CLI `bencher mock`][bencher mock]
con [la opción `--measure`][measure option]
para generar datos ficticios BMF con múltiples Medidas.
Lo utilizaremos como un marcador de posición para tu propio ejecutor de benchmark personalizado.
Usando <code><a href="/es/docs/explanation/bencher-run/">bencher run</a></code>
y [el adaptador `json`][json adapter]
podemos rastrear nuestros benchmarks con múltiples Medidas con el siguiente comando:

Si tu arnés de benchmark informa más Medidas de las que quieres rastrear,
usa [la opción `--measure`][run measure option] de <code><a href="/es/docs/explanation/bencher-run/">bencher run</a></code>
para conservar solo las Medidas que nombres.
Cualquier otra Medida se descarta antes de guardarse.
Esto es distinto de la opción `--measure` de `bencher mock`,
que establece las Medidas que genera `bencher mock`.
