### `plus.registry`

このセクションでは、OCI（Open Container Initiative）レジストリストレージの設定を指定します。
BencherはOCI準拠のコンテナ/アーティファクトレジストリとして機能できます。

このセクションが設定されていない場合、Bencherはデータベースファイルと同じ階層の
`registry`ディレクトリにローカルファイルシステムストレージを使用します。
これは開発や単一インスタンスのデプロイメントに適しています。

複数インスタンスの本番デプロイメントや耐久性のためには、
S3互換のストレージを設定してください。

2つのストレージ`scheme`があります：
- `file`：ローカルファイルシステムにOCIアーティファクトを保存（デフォルト）
    - `path`：(任意) レジストリデータのディレクトリ。デフォルトはデータベースファイルと同じ階層の`registry`ディレクトリ。
- `s3`：S3互換の任意のブロブストレージにOCIアーティファクトを保存
    - `bucket`：バケット名
    - `path`：(任意) バケット内のキープレフィックス。先頭、末尾、および連続するスラッシュは削除されるため、`registry`、`registry/`、`/registry` はすべて `registry` の下に保存されます。
    - `endpoint`：(AWS: 任意 | 非AWS: 必須) ストレージエンドポイント
    - `region`：(任意) バケットのリージョン。AWSでは必須。デフォルトは`auto`で、S3互換ストレージが期待する値です。
    - `access_key_id`：S3アクセスキー
    - `secret_access_key`：S3シークレットアクセスキー
    - `chunk_size`：(任意) 保存する前のアップロードデータのバッファリング用最小チャンクサイズ（バイト）。デフォルト：5 MB。
      HTTPリクエストボディは小さなネットワークフレーム（通常8〜64 KB）として到着します。バッファリングなしでは、各フレームが個別のオブジェクトとして保存され、レイヤーごとに数千のオブジェクトが作成されます。この値はS3マルチパートアップロードの最小パートサイズにも対応しています。

未完了のマルチパートアップロードを中止するバケットのライフサイクルルールを設定してください。Blobアップロードの完了途中でクラッシュすると未完了のマルチパートアップロードが残り、サーバーはそれを中止しません。

以前にスラッシュで始まるまたは終わる `path` を設定していた場合は、アップグレード前に既存のオブジェクトを正規化されたプレフィックスに移動してください。`path` が `registry/` の場合、キーは `registry//<project>/...` に保存されていましたが、現在は `registry/<project>/...` に保存されます。`A-Za-z0-9._-/` 以外の文字を含む `path` は保存されるキーでパーセントエンコードされるため（`team#1` は `team%231` になります）、以前のリリースがそのようなプレフィックスの下に保存したデータにも同じ移動が必要です。

|      名前      |                   例                   | デフォルト |  必須  |                     説明                      |
| :------------: | :------------------------------------: | :--------: | :----: | :-------------------------------------------: |
|      url       | "https://registry.bencher.example.com" | "http://localhost:6610" | いいえ | OCIレジストリアクセス用のAPIサーバーの外部到達可能なURL。 |
|    storage     |               \{ ... \}                |    ---     | いいえ | レジストリストレージバックエンドを指定します。省略時はローカルファイル。 |
| storage.scheme |                 "s3"                   |    ---     |  はい  | ストレージ`scheme`を指定します。その他の`storage`キーについては上記のリストを参照してください。 |
| upload_timeout |                  3600                  |    3600    | いいえ | アップロードセッションのタイムアウト（秒）。古いアップロードは新しいアップロード開始時にクリーンアップされます。 |
| max_body_size  |               1073741824               | 1073741824 | いいえ | Blobおよびマニフェストアップロードの最大ボディサイズ（バイト）。この制限を超えるリクエストは413 Payload Too Largeで拒否されます。デフォルト：1 GiB。 |
