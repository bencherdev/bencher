In diesem Beispiel ist der Schlüssel `benchmark_name` der Name eines [Benchmarks][benchmark].
Ein Benchmark kann anhand seines Namens, Slugs oder seiner UUID identifiziert werden.
Der Schlüssel `benchmark_name` verweist auf eine Liste von Einträgen,
und jeder Eintrag hat ein `measures`-Objekt.
Das `measures`-Objekt kann mehrere [Measure][measure]-Namen, Slugs oder UUIDs als Schlüssel enthalten.
Wenn der angegebene Wert ein Name oder Slug ist und die Measure noch nicht existiert, wird sie für Sie erstellt.
Ist der angegebene Wert jedoch eine UUID, muss die Measure bereits existieren.
In diesem Beispiel ist `latency` der Slug für die eingebaute Latency-Measure.
Jedes Projekt verfügt standardmäßig über eine Latency-Measure (d. h. `latency`) und eine Throughput-Measure (d. h. `throughput`),
die jeweils in `nanosecond (ns)` bzw. `operations / second (ops/s)` gemessen werden.
Jedes Measure-Objekt ordnet [Metrik][metric]-Namen ihren Werten zu.
Wenn Ihr Benchmark-Harness für eine Measure ein einzelnes Ergebnis meldet,
nennen Sie seine Metrik `value`.

In diesem Beispiel enthält das `latency`-Measure-Objekt eine `value`-Metrik von `88.0`.

Ein Eintrag kann auch ein `parameters`-Objekt haben, zum Beispiel `{"size": 64}`.
Jeder Satz von [Parametern][parameters] ist eine eigene [Variante][variant] des Benchmarks,
sodass ein Benchmark mehrere Varianten haben kann.
Ein Eintrag ohne `parameters` ist die Variante des Benchmarks ohne Parameter.
