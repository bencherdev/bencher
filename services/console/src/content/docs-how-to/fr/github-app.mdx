Si vous utilisez Bencher Cloud, vous pouvez simplement vous [inscrire](/auth/signup) ou vous [connecter](/auth/login)
en utilisant le bouton `GitHub`.

Pour Bencher Self-Hosted, vous devrez disposer d'un [plan Bencher Plus Enterprise][bencher plus enterprise], créer votre propre application GitHub et mettre à jour votre [configuration de la console][console config] et la [configuration du serveur API][server config].

[console config]: /fr/docs/reference/console-config/

## Créer une application GitHub

- Créez une [Application GitHub](https://docs.github.com/fr/apps/creating-github-apps/registering-a-github-app/registering-a-github-app#registering-a-github-app)
- Nom de l'application GitHub
  - Choisissez un nom unique (ex : `Bencher pour Mon Entreprise`)
- URL de la page d'accueil
  - Réglez-le sur votre URL de Console Bencher Auto-Hébergé (ex : `https://bencher.example.com`)
- Identification et autorisation des utilisateurs
  - URL de rappel
    - Réglez l'URL de rappel sur l'URL de votre Console Bencher Auto-Hébergé avec le chemin `/auth/github` (ex : `https://bencher.example.com/auth/github`)
  - ✅ Expirez les jetons d'autorisation des utilisateurs
  - ✅ Demandez l'autorisation de l'utilisateur (OAuth) pendant l'installation
  - ✅ Activez le flux de l'appareil
- Webhook
  - ❌ Active - Décocher cette case
- Permissions
  - Permissions du compte
    - Adresses email : `Lecture seule`
- Où cette application GitHub peut-elle être installée ?
  - 🔘 N'importe quel compte
- Cliquez sur `Créer une application GitHub`
- Maintenant sous `Général` pour l'application nouvellement créée
- Notez le `Client ID` (ex : `Iv1.12864abcd1232048`)
- Secrets du client
  - Cliquez sur `Générer un nouveau secret client`
  - Notez ce secret (ex : `00000abcd12345wxyz123456789abcdefgh0000`)
- Ajoutez le [logo PNG de Bencher](/brand/) sous les informations d'affichage
- Clés privées
  - Cliquez sur `Générer une clé privée`

## Configuration de l'application GitHub

### Interface utilisateur de la console
Définissez la variable d'environnement `GITHUB_CLIENT_ID` lorsque vous exécutez l'image Docker `bencher-console`. (ex : `GITHUB_CLIENT_ID=Iv1.12864abcd1232048`) Si l'ID du client est manquant, alors les boutons GitHub n'apparaîtront pas dans l'UI.

### Serveur API
Ajoutez le `client_id` et le `client_secret` à [la section `plus.github` de la config du serveur](/fr/docs/reference/server-config/#plusgithub). Si la section GitHub est manquante, alors le serveur échouera pour toute demande d'authentification GitHub.

## Dépôts liés

Ces paramètres nécessitent le serveur API et la Console Bencher Auto-Hébergé en `v0.6.18` ou une version ultérieure.

Pour qu'un Projet puisse [lier un dépôt GitHub][linked repository] pour ses exécutions détachées,
réglez aussi ces paramètres pour l'application GitHub :

- Identification et autorisation des utilisateurs
  - URL de rappel
    - Réglez la première URL de rappel sur l'URL de votre Console Bencher Auto-Hébergé avec le chemin `/console/github` (ex : `https://bencher.example.com/console/github`).
      GitHub envoie l'utilisateur vers la première URL de rappel après qu'il a installé l'application.
    - Gardez ensuite l'URL de rappel avec le chemin `/auth/github`, pour la connexion (ex : `https://bencher.example.com/auth/github`).
      GitHub refuse une connexion dont l'URL de rappel n'est pas listée.
  - ✅ Demandez l'autorisation de l'utilisateur (OAuth) pendant l'installation
- Webhook
  - ✅ Active - Cochez cette case
  - URL du webhook
    - Réglez-la sur l'URL de votre serveur API Bencher Auto-Hébergé avec le chemin `/v0/github/webhook` (ex : `https://api.bencher.example.com/v0/github/webhook`)
  - Secret du webhook
    - Saisissez un secret aléatoire et notez-le (ex : `0123456789abcdef0123456789abcdef`)
- Permissions
  - Permissions du dépôt
    - Checks : `Lecture et écriture`
    - Contenu : `Lecture seule`
    - Pull requests : `Lecture et écriture`
  - S'abonner aux événements
    - Laissez chaque événement décoché
- Notez le slug de l'application, la dernière partie de l'URL de sa page publique (ex : `my-bencher-app` dans `https://github.com/apps/my-bencher-app`)

Ajoutez le slug, la clé privée et le secret du webhook en tant que `app` à [la section `plus.github` de la config du serveur](/fr/docs/reference/server-config/#plusgithub).

Pour mettre à jour une application qu'une version antérieure a configurée avec Contenu : `Lecture et écriture` :

1. Ajoutez Checks et Pull requests avant la mise à jour.
   GitHub demande au propriétaire de chaque installation de les approuver.
2. Mettez à jour le serveur API et la Console vers `v0.6.18` ou une version ultérieure.
   Après la mise à jour, un dépôt dont l'installation n'a pas approuvé les nouvelles permissions ne peut pas être lié, et Bencher ne peut rien y publier.
3. Passez Contenu à `Lecture seule`, dans une modification séparée.

## GitHub Enterprise Server

Pour utiliser GitHub Enterprise Server à la place de github.com, enregistrez l'application GitHub sur votre GitHub Enterprise Server avec les paramètres ci-dessus.
Puis définissez `server_url` dans [la section `plus.github` de la config du serveur](/fr/docs/reference/server-config/#plusgithub) sur sa racine web (ex : `https://github.example.com`).
Bencher l'utilise alors pour la connexion, les dépôts liés, les titres des commits, ainsi que les GitHub Checks et les commentaires de pull request des exécutions détachées.
Le slug de l'application est la dernière partie de l'URL de sa page publique (ex : `my-bencher-app` dans `https://github.example.com/github-apps/my-bencher-app`).

Cela nécessite le serveur API Bencher Self-Hosted en `v0.6.18` ou ultérieure,
et une licence Bencher Plus Enterprise valide pour au moins une organisation sur le serveur.
Sans la licence, Bencher refuse la connexion avec GitHub, la liaison et les exécutions détachées sur GitHub Actions, et ne récupère aucun titre de commit.
Bencher publie pour une exécution détachée seulement quand son workflow s'exécute sur le même GitHub Enterprise Server :
il refuse une exécution dont le `GITHUB_API_URL` est l'API de tout autre GitHub.
