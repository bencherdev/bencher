## Жизненный цикл Job

Каждая Job проходит через фиксированный набор состояний по мере того, как её берут, выполняют и обрабатывают.

| Из        | В           | Триггер                                                                |
| --------- | ----------- | ---------------------------------------------------------------------- |
| pending   | claimed     | Runner берёт Job                                                        |
| pending   | canceled    | Пользователь отменяет Job                                              |
| claimed   | running     | Runner отправляет `running`                                            |
| claimed   | failed      | Runner отправляет `failed`                                             |
| claimed   | unknown     | Сервер теряет связь с Runner                                           |
| claimed   | canceled    | Пользователь отменяет Job                                              |
| running   | completed   | Runner отправляет `completed`                                          |
| running   | failed      | Runner отправляет `failed`                                             |
| running   | unknown     | Сервер теряет связь с Runner                                           |
| running   | canceled    | Пользователь отменяет Job, или превышен жёсткий тайм-аут Job           |
| unknown   | completed   | Runner отправляет `completed`                                          |
| unknown   | failed      | Runner отправляет `failed`                                             |
| unknown   | canceled    | Пользователь отменяет Job, или превышен жёсткий тайм-аут Job           |
| completed | processed   | Сервер успешно обрабатывает результаты                                 |
| completed | failed      | Сервер не может обработать результаты                                  |
| completed | unknown     | При запуске сервер обнаруживает, что сохранённые результаты потеряны   |

`processed`, `failed` и `canceled` являются терминальными: Job в состоянии `failed` или `canceled` больше никогда не меняет состояние.
`completed` является квази-терминальным:
`completed` переходит в `processed`, как только результаты разобраны, в `failed`, если их не удаётся обработать, или в `unknown`, если при запуске сервер обнаруживает, что они потеряны.
`unknown` означает, что сервер потерял связь с Runner и ещё не знает результат.
Состояние разрешается, когда Runner снова выходит на связь, с результатом, который он отправляет,
или как `canceled`, когда истекает срок Job.
Каждый переход использует фильтр по статусу в своём обновлении базы данных,
поэтому Job, изменённая конкурентно, перечитывается, а не перезаписывается.
