## Несколько Измерений

В [Bencher Metric Format (BMF) JSON][bmf]
объект `measures` записи [Бенчмарка][benchmark] может содержать в качестве ключей несколько имен, slug или UUID [Измерений][measure].
Если указано имя или slug и такое Измерение еще не существует, оно будет создано автоматически.
Однако если указан UUID, то Измерение должно уже существовать.
Каждый объект Измерения сопоставляет имена [Метрик][metric] с их значениями.

<BmfMultiExample />

В этом примере объект Измерения `latency` содержит Метрику `value`, равную `88.0`,
а объект Измерения `throughput` содержит Метрику `value`, равную `5.55`.

Вы можете использовать [подкоманду CLI `bencher mock`][bencher mock]
с [опцией `--measure`][measure option]
для генерации фиктивных данных BMF с несколькими Измерениями.
Мы будем использовать ее как заполнитель для вашего собственного инструмента запуска бенчмарков.
Используя <code><a href="/ru/docs/explanation/bencher-run/">bencher run</a></code>
и [адаптер `json`][json adapter],
мы можем отслеживать наши бенчмарки с несколькими Измерениями с помощью следующей команды:

<RunCmdMultiExample />

Если ваша оболочка бенчмаркинга сообщает больше Измерений, чем вы хотите отслеживать,
используйте [опцию `--measure`][run measure option] команды <code><a href="/ru/docs/explanation/bencher-run/">bencher run</a></code>,
чтобы сохранить только перечисленные Измерения.
Все остальные Измерения отбрасываются до сохранения.
Это отличается от опции `--measure` команды `bencher mock`,
которая задает Измерения, генерируемые `bencher mock`.
