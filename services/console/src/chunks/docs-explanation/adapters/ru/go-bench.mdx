## 🕳 Go Bench

Адаптер Go Bench (`go_bench`) ожидает вывод [go test -bench](https://pkg.go.dev/testing#hdr-Benchmarks).

Имя Бенчмарка состоит из пакета, `.` и бенчмарка (то есть `example.com/sort.BenchmarkSort`),
без суффикса `-N` и частей `key=value`.
Суффикс `-N` становится Параметром `@gomaxprocs`, который равен `1`, если Go не печатает суффикс,
а каждая часть `key=value` в имени под-бенчмарка становится Параметром с этим ключом, причем числовое значение хранится как число.
Часть с ключом `@gomaxprocs` учитывается как пропущенная в замечаниях Отчета.
При `GOMAXPROCS=1` Go не печатает суффикс, поэтому имя под-бенчмарка, которое само заканчивается на `-N`, читается как этот `@gomaxprocs`.

Измерение `latency` (то есть `ns/op`) собирается в наносекундах (ns).
С `-benchmem` также собираются Измерения `allocated` (то есть `B/op`) и `allocations` (то есть `allocs/op`),
а с `b.SetBytes` Измерение `bytes-throughput` (то есть `MB/s`) в байтах в секунду.
Каждая пользовательская единица из `b.ReportMetric` является Измерением, названным по этой единице так, как ее печатает Go.
Для одиночного запуска каждое значение на операцию (то есть единица, оканчивающаяся на `/op`) и скорость `MB/s` являются `mean`, а значение в любой другой единице является `value`.
С `-count` запуски каждого Варианта объединяются в их `mean`, `median`, `min`, `max` и `std_dev`.

С `-count` в первую очередь задайте Порог для Метрики `median` с помощью `--threshold-metric median`.
Для одиночного запуска в первую очередь задайте Порог для `mean`, или для `value` у пользовательской единицы, которая не оканчивается на `/op`.

<details>
<summary>BMF версия 0</summary>

В BMF версии 0 читается только текстовый вывод, а именем Бенчмарка является имя в том виде, в каком его печатает Go.
Собирается только Измерение `latency` (то есть `nanoseconds (ns)`).
Доступно только среднее (то есть `value`).
Ни `lower_value`, ни `upper_value` не собираются.

</details>
