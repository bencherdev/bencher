### `--github-actions <GITHUB_TOKEN>`

<br />

Необязательно: Установите токен аутентификации API GitHub. Самый удобный способ сделать это - использовать [переменную окружения `GITHUB_TOKEN` в GitHub Actions][github token] (например, `--github-actions ${{ secrets.GITHUB_TOKEN }}`).

Результаты будут добавлены к head-коммиту как проверка GitHub с именем:

1. `Bencher Report (<ID>)`, если задана [опция `--ci-id`](#--ci-id-id)
2. `Bencher Report (<ИМЯ ПРОЕКТА>)` для существующих проектов
3. `Bencher Report` для динамических проектов [`--ci-on-the-fly`](#--ci-on-the-fly) (пока проверка выполняется)

Это требует, чтобы у токена были [полномочия `checks` с разрешениями на `write`][github token permissions]. Если проверку GitHub не удается создать, `bencher run` запишет предупреждение в журнал и продолжит работу.

Когда `bencher run` используется как часть запроса на вытягивание, результаты также будут добавлены в запрос как комментарий. Все задания Проекта в запросе на вытягивание используют этот один общий комментарий, с одной строкой Отчета для каждого задания. Это требует, чтобы у токена были [полномочия `pull-requests` с разрешениями на `write`][github token permissions]. Результаты также всегда будут добавлены в сводку задания. С [флагом `--detach`](/ru/docs/explanation/images/#--detach) отсоединенный запуск не публикует комментарий и не пишет сводку задания, а [подключение с помощью `--job`](/ru/docs/explanation/images/#--job-uuid) завершает проверку GitHub, которую он запустил (см. [опцию `--ci-callback-token`](#--ci-callback-token-token)).

Если строк две или больше, комментарий показывает таблицу сводки каждого Отчета с его Тестовой средой, Адаптером и статусом (`Pending`, число предупреждений, `No Alerts` или `Failed`). Строки идут в порядке запуска Отчетов и пронумерованы с 1, так же как Console перечисляет Отчеты одного запуска. Подпись каждой строки состоит из ее номера, за которым в скобках следует значение [опции `--ci-id`](#--ci-id-id), если она задана (пример: `2 (microbench)`). Подпись ведет на Отчет, Тестовая среда на ее страницу в Console, а Адаптер на его часть [документации по Адаптерам](/ru/docs/explanation/adapters/). Если задания используют больше одной Ветки, в таблицу сводки добавляется столбец для Ветки. Далее одна таблица содержит предупреждения всех Отчетов, со столбцом для Отчета. Затем результаты каждого Отчета следуют в сворачиваемом блоке (пример: `Report 2 (microbench): 14 benchmarks, 2 alerts`), который открыт, если в Отчете есть предупреждения. Каждое задание сохраняет свою проверку GitHub и свою сводку задания, поэтому имена проверок GitHub и обязательные проверки статуса не меняются. Задание, чей коммит больше не является head-коммитом запроса на вытягивание, оставляет комментарий без изменений. Если токен не может прочитать запрос на вытягивание, то задание запишет предупреждение в журнал и напишет комментарий без проверки head-коммита.

У комментария GitHub есть ограничение размера, поэтому комментарий использует первую из этих форм, которая помещается:

1. Все части выше
2. Без сворачиваемых блоков, с пометкой, что комментарий сокращен
3. Каждая строка сводки и общее число предупреждений, без строк предупреждений
4. В крайнем случае первые строки сводки, а затем `and N more reports` для остальных

С одной строкой комментарий такой же, как раньше, а если он слишком большой, он ведет на полный Отчет.

Чтобы найти другие задания, `bencher run` получает список проверок GitHub для head-коммита, что уже разрешают указанные выше полномочия `checks` с разрешениями на `write`. Если задание не может создать или завершить свою проверку GitHub, не может определить, какому GitHub App она принадлежит, или не может получить список проверок GitHub, то оно опубликует комментарий только со своими результатами. Комментарии Проекта от более ранней версии `bencher run` заменяются: первое задание, которое пишет общий комментарий, обновляет самый старый из них и удаляет остальные. При записи общего комментария задание обновляет или удаляет только комментарии, опубликованные GitHub App, которому принадлежит его проверка GitHub, то есть ботом `github-actions` при использовании `GITHUB_TOKEN`.

[github token permissions]: https://docs.github.com/ru/actions/security-for-github-actions/security-guides/automatic-token-authentication#permissions-for-the-github_token

> - `GITHUB_ACTIONS`
> - `GITHUB_EVENT_NAME`
> - `GITHUB_EVENT_PATH`
> - `GITHUB_SHA`
> - `GITHUB_API_URL` (GitHub Enterprise Server только)
