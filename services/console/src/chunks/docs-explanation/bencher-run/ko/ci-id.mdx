### `--ci-id <ID>`

<br />

선택 사항: CI에 결과를 게시하기 위한 사용자 정의 ID입니다. pull request에서 프로젝트의 모든 작업은 하나의 댓글을 공유하며, 각 작업마다 하나의 보고서 행이 있습니다. ID를 지정하면 행의 레이블은 행 번호와 ID가 됩니다(예: `2 (microbench)`). 작업의 보고서가 존재하기 전까지 해당 행은 번호 없이 ID만 표시하며(예: `(microbench)`), 작업이 실행되는 동안에는 `Pending`으로 나타나고, 번호가 매겨진 행 뒤에 옵니다. ID를 지정하지 않으면 레이블은 번호뿐이며, 작업의 보고서가 존재하면 행이 나타납니다. 기본적으로, 브랜치, 테스트베드 및 [어댑터](/ko/docs/explanation/adapters/)의 조합이 같은 작업은 하나의 행을 공유하며, 설정된 경우 [`--build-time`](#--build-time) 및 [`--file-size`](#--file-size-file)도 이 조합에 포함됩니다. Bencher가 동일한 커밋에서 동일한 프로젝트, 브랜치, 테스트베드 및 어댑터 조합으로 여러 번 실행될 때 각 실행이 자체 행을 갖도록 사용자 정의 ID를 설정하는 것이 유용합니다. 예를 들어, 같은 브랜치에서의 `push` 실행과 `pull_request` 실행은 헤드 커밋을 공유하므로, 각 실행에 고유한 ID를 지정하거나 `push` 실행에서는 `--github-actions`를 사용하지 마세요. 그렇지 않으면 두 실행은 하나의 행을 공유하여 그중 하나만 표시되며, 더 최근 실행이 그 행을 차지하면 이전 실행은 아무것도 작성하지 않습니다. 이 ID는 GitHub Check 이름에서 프로젝트 이름 대신 사용되므로(예: `Bencher Report (<ID>)`), 각 호출이 별도의 필수 상태 검사로 사용할 수 있는 안정적인 이름을 갖게 됩니다. 필요 사항: `--github-actions`
