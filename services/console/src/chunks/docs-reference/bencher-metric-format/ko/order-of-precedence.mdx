## 우선순위

다음은 [벤치마크][benchmark]를 식별할 때의 우선순위입니다:

1. `UUID`
2. 케밥 케이스 `name`에 `-bencher-ignore` 접미사가 있으면 접미사는 제거되어 [경고 억제][suppressing alerts]에 사용됩니다(최대 길이 `1024`자)
3. `slug` (최대 길이 `64`자)
4. `name` (최대 길이 `1024`자)

<br />

다음은 [측정][measure]을 식별할 때의 우선순위입니다:

1. `UUID`
2. `slug` (최대 길이 `64`자)
3. `name` (최대 길이 `64`자)

<br />

[메트릭][metric]과 [매개변수(Parameters)][parameters]에는 다음과 같은 제한이 있습니다:

- 메트릭 이름은 `1`자에서 `64`자이며, 앞뒤에 공백이 없어야 합니다.
  `value`, `lower_value`, `upper_value`는 관례적인 이름일 뿐 특별한 이름이 아닙니다.
- 하나의 측정은 최대 `32`개의 메트릭 이름을 가질 수 있습니다.
  `32`개를 넘으면 `value`, `lower_value`, `upper_value`가 유지되고, 그다음 나머지 이름이 알파벳순으로 유지되며, 그 외는 건너뜁니다.
- 변형(Variant)의 매개변수는 최대 `8`개의 키를 가질 수 있습니다.
  키는 `1`자에서 `64`자이며, 앞뒤에 공백이 없어야 합니다.
  값은 불리언, 숫자 또는 최대 `64`자의 문자열이며, 빈 문자열일 수도 있습니다.
- 매개변수는 [RFC 8785][rfc 8785]로 정규화되므로,
  키의 순서는 상관없고 `16`, `16.0`, `1.6e1`은 같은 값입니다.

제한을 벗어난 벤치마크, 측정 또는 메트릭 이름은 건너뛰며,
매개변수가 제한을 벗어난 변형도 마찬가지로 건너뜁니다.
보고서는 각각을 warning에 집계합니다.
값이 숫자가 아닌 메트릭이 있으면 전체 페이로드가 실패합니다.
