### `--ci-callback-token <TOKEN>`

<br />

선택 사항: 분리된 [베어 메탈 Job][job]의 콜백에 사용할 GitHub 토큰을 설정하여, 두 번째 워크플로가 그 결과를 게시할 수 있게 합니다.
[`--detach` 플래그][detach]와 [`--github-actions` 옵션](#--github-actions-github_token)을 함께 사용하면,
`bencher run`은 진행 중인 GitHub Check를 시작하고, Job을 제출하고, 그 밖에는 아무것도 게시하지 않고 종료합니다.
[콜백](/ko/docs/explanation/images/#--callback-url-url)은 `bencher run`이 직접 작성합니다.
이는 `bencher_run` 유형의 [`repository_dispatch`][github repository dispatch] 이벤트이며, 이 토큰으로 저장소에 전송됩니다.
이벤트의 `client_payload`에는 Job UUID(`job`), 프로젝트 슬러그(`project`),
pull request 번호(`number`, 워크플로가 `pull_request` 또는 `pull_request_target` 이벤트에서 실행되지 않고 `--ci-number`도 설정하지 않으면 없음), 헤드 커밋(`sha`),
GitHub Check ID(`check`, GitHub Check 시작에 실패하면 없으며, 이 경우 `bencher run --job`이 `sha`에 GitHub Check를 생성함), `--ci-id`(`ci_id`, 설정하지 않으면 없음)가 담깁니다.
그 이벤트로 실행되는 두 번째 워크플로는 [`--job`으로 Job에 연결](/ko/docs/explanation/images/#--job-uuid)하고
GitHub Check와 pull request 댓글을 완료합니다.
두 워크플로 모두 [GitHub Actions의 베어 메탈에서의 Pull Requests][pull requests on bare metal]를 참조하세요.

Bencher는 보통 분리된 워크플로가 끝난 뒤에 이벤트를 보내며, 그 워크플로의 `GITHUB_TOKEN`은 워크플로와 함께 만료됩니다.
따라서 이 옵션에는 그 하나의 저장소에 대해 `Contents` `write` 권한을 가진 [fine-grained personal access token][github fine-grained token]을 지정합니다.
이는 `repository_dispatch`가 받아들이는 최소 권한입니다.
토큰은 모든 출력에서 가려집니다.
두 워크플로 모두에서 `--github-actions`는 워크플로 자체의 `GITHUB_TOKEN`으로 유지하세요.
GitHub Check를 만들거나 업데이트할 수 있는 것은 GitHub App뿐이므로, 그 자리에 personal access token을 쓰면 GitHub Check가 생성되지 않습니다.
또한 두 워크플로는 GitHub Actions 앱을 공유하므로, 두 번째 워크플로가 첫 번째가 시작한 GitHub Check를 완료할 수 있습니다.

`--github-actions`와 함께 쓰는 `--detach`에는 `--ci-callback-token` 또는 [`--callback-url`](/ko/docs/explanation/images/#--callback-url-url)이 필요합니다.
그렇지 않으면 시작한 GitHub Check를 완료할 것이 아무것도 없기 때문입니다.
설정되지 않은 저장소 시크릿처럼 비어 있는 토큰도 거부됩니다.
명시적인 `--callback-url`은 직접 운영하는 수신 측을 위해 `repository_dispatch` 콜백을 대체합니다.
이 경우에도 GitHub Check는 시작되며, 이를 완료하는 일은 그 수신 측에 맡겨집니다.
조직이 Bencher Plus 플랜을 사용하지 않아 콜백이 건너뛰어진 경우,
`bencher run`은 해당 알림과 함께 GitHub Check를 `neutral`로 완료합니다.
제출 후 콜백 상태를 읽을 수 없으면, `bencher run`은 경고를 출력하고 `--job` 연결이 완료할 수 있도록 GitHub Check를 진행 중으로 둡니다.
GitHub Actions 밖에서는 이 옵션이 무시됩니다.
이 옵션은 [`--github-actions` 옵션](#--github-actions-github_token)과 [`--detach` 플래그][detach]가 설정되어 있어야 합니다.
