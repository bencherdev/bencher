## 2026 年谁还没造过 Harness？

在构建 Bencher Bare Metal 的同时，我还让 Claude 为它自己打造了管理机群的工具。这包括两部分：`bencher` 仓库中一个处理日常任务的 CLI，以及一个新的元仓库（meta-repo）。这个元仓库存放着 Bencher 作为一款产品的所有文档和上下文。`bencherdev` GitHub 组织中的其他每个仓库，都是这个元仓库中的子模块。有了元仓库，智能体就能轻松处理可能横跨多个仓库的任务，还能撰写那些我不希望公开的文档（产品战略、事故报告等等）。

我想在 Claude Code CLI 之上构建我自己的智能体，让这个元仓库从一个静态产物变成开发周期中主动参与的一环。Fable 5 一推出，我就把大量精力投入到了构建这个智能体上。我希望能够放心地让这个智能体自主运行。其中很大一部分在于安全性（即缓解提示词注入）。我的设计是让工作智能体永远不持有任何密钥。所有密钥都由网络代理注入，并且仅限于白名单中的端点。智能体本身运行在另一个 Firecracker microVM 中，这次支持并行。智能体控制机和网络代理加沙箱分别运行在完全不同的主机上。

我的宏伟愿景是，界面是一个按任务优先级排序的队列。也就是说，这个智能体的目标是向我展示在那一刻*最*重要的任务。Facebook/Instagram/Twitter/X/TikTok 的信息流是为参与度而优化的，而这个信息流则是为对我的重要性而优化的。

我想打造一个工具，把我自己置于 [A~~P~~I 之下][replace with api]。我发现自己大部分时间都花在了上下文切换和在各个线程之间来回跳转上。我希望智能体能通过帮我对事情进行排序，来减轻这种手忙脚乱。借助一个类似 Reddit 的点赞/点踩系统，我就可以训练智能体判断那条新的 Slack 消息是否真的是我最该关注的事情。

我还发现，我现在的工作很大一部分是当我智能体的鲁伯·海格，也就是它的“钥匙保管员”。在网络代理层进行注入，再配合受限的端点白名单，是 Claude 和我能想出来的最好办法：既能让智能体永远接触不到任何密钥，又能让它开箱即用地使用 `gh` CLI 之类的工具。

另一个核心目标是*永远*不离开智能体界面。无论出于什么原因离开智能体去别处操作，都被视为 harness 的失败。我创建了一个程序化 UI 组件系统，让处理任务的智能体可以根据手头的任务即时构建一个全新的界面，或者从组件库中选择一个现有组件。代码、邮件、Slack、日历、生产环境遥测数据、错误监控，所有东西都在一个界面里，都在一个按优先级排序的队列里。

我已经把这一切的最小可用版本跑起来了。不过，仍然有很多粗糙的地方。目前，如果我直接用 Claude 桌面应用，效率反而要高得多。而就眼下而言，我需要尽可能多的即时生产力，才能跟上需求。
