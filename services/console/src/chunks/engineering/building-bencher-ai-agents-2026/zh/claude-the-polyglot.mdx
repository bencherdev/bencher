## 精通多国语言的 Claude

早在 2023 年，我就决定让 Bencher 文档支持 9 种语言：英语、中文、西班牙语、巴西葡萄牙语、俄语、日语、法语、德语和韩语。我是怎么选出这九种语言的？它们正是 GitHub 文档所使用的语言，所以我觉得这是个足够好的近似。唯一的问题是，我只会说英语。于是我让 GPT-4 帮我翻译文档。当时 GPT-4 的上下文窗口只有 8k token。这意味着我必须把所有文档页面拆分成一个个小于 8k token 的“块”（chunk）。然后我还得写一个 CLI 工具，来处理块的翻译，以及在块更新后频繁地重新翻译。

这是一个非常繁琐且容易出错的过程。我不得不手动编辑翻译后的文件，因为即使在系统提示词里写了非常明确的指令，模型仍然会把导入路径搞砸，或者把所有内容又塞进一层 Markdown 代码块里，不知为何，日语尤其如此。

自从我开始用 Claude Code 搭配 Opus 4.5，这些问题全都消失了。现在智能体直接就搞定了。什么算一个块，这个约定就写在代码库里，Claude 照着做就行。在我为 Bencher Bare Metal 编写技术文档时，Claude 直接包办了分块和翻译的编排工作。尽管现在的上下文大小已经完全足以容纳一整个页面，我还是喜欢保留这些块。它有助于让改动保持隔离，这样修订时只有页面中相关的部分才会被重新翻译。
