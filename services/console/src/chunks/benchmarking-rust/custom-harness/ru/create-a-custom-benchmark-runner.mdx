### Создание настраиваемого запускающего субъекта для тестов производительности

Наконец, нам нужно создать запускающий субъект для нашего пользовательского тестового комплекта.
Пользовательский тестовый комплект на самом деле является просто исполняемым файлом,
который запускает все наши тесты и сообщает их результаты.
Запускающий субъект отвечает за управление этим процессом.

Мы хотим, чтобы наши результаты выводились в [формате Bencher Metric Format (BMF) JSON][bmf json] версии 1.
Для этого нам нужно добавить одну последнюю зависимость,
[пакет `serde_json`][crates serde json] от... вы угадали, Дэвида Толная!

Далее мы реализуем метод для `CustomBenchmark`, чтобы запустить его функцию тестирования
и затем вернуть результаты в виде BMF JSON.

<PlayGameRsRun />

У каждого бенчмарка в результатах BMF JSON есть единственный [Вариант][variant] без Параметров, и этот Вариант содержит шесть [Измерений][measures]. Каждое Измерение является точным подсчетом, поэтому у него одна [Метрика][metric], `value`:

- Final Blocks: итоговое количество выделенных блоков при завершении теста.
- Final Bytes: итоговое количество выделенных байтов при завершении теста.
- Max Blocks: максимальное количество блоков, выделенных в любое время во время теста.
- Max Bytes: максимальное количество байтов, выделенных в любое время во время теста.
- Total Blocks: общее количество блоков, выделенных во время теста.
- Total Bytes: общее количество байтов, выделенных во время теста.

Наконец, мы можем создать функцию `main` для выполнения всех тестов в нашей коллекции `inventory`
и вывести результаты в виде BMF JSON.
