## 私の今のコーディング

GitHub Copilotを使っていた頃、それはVSCodeの拡張機能でした。Claude Codeに乗り換えた当初は、CLIを使っていました。3つのターミナルウィンドウを、それぞれ別のmacOSのSpaceに置いていました。各ターミナルウィンドウにはタブが2つありました。1つのタブはClaude用、もう1つは[Jujutsu（`jj`）][github jj]用です。バージョン管理と`jj`ワークスペースは、まだ自分で管理していました。

今では、Claude Codeのデスクトップアプリを使うだけです。新しいセッションはすべて、`worktree`チェックボックスを有効にした状態で、自分のメタリポから始めます。Plan modeは数か月前に使わなくなりました。Matt Pocockの[`/grill-me`スキル][github grill me]はインストールしませんでした。プロンプトでClaudeに「すべての設計判断について私を問い詰めて」と頼むだけで、今ではモデルがどうすればいいかわかっています。私の ~~`CLAUDE.md`~~ `AGENTS.md`は、モデルにどう振る舞ってほしいかに合わせてかなりうまく調整されています。

Claude ReviewのCIワークフローは、ほぼ廃止しました。今ではエージェントが、私が頼むまでもなく、ローカルで敵対的レビュアーを立ち上げてくれます。そして両者は収束するまで反復し、ときには6ラウンドほどになることもあります。開発作業を外部の作業用マシンにオフロードし、ローカルマシンはオーケストレーターとしてだけ残すという実験も始めました。

私が自分でバージョン管理に触るのは、自分で何かをテストするためにビルドをチェックアウトしようとするときか、Bencherのタグ付きのバージョンリリースを作るときだけです。それぞれ週に1回程度、月に1回程度です。それ以外は、今ではすべてClaudeに任せています。ドラフトPRをたっぷり活用していますし、GitHubで使えるようになった今では、スタックPRも活用しています。PRが開かれるまでコードは見ません。Bencherのコードには今でも一通り目を通しますが、今では本当のコードレビューというより、ざっと妥当性を確かめるサニティチェックに近いものです。
