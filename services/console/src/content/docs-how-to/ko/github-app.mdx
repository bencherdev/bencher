Bencher Cloud를 사용하고 있다면, 단순히 `GitHub` 버튼을 통해 [가입](/auth/signup) 또는 [로그인](/auth/login)하면 됩니다.

Bencher Self-Hosted를 사용하려면 [Bencher Plus Enterprise 요금제][bencher plus enterprise]가 필요하고, 자체 GitHub 앱을 생성하고 [콘솔 구성][console config]과 [API 서버 구성][server config]을 업데이트해야 합니다.

[bencher plus enterprise]: /pricing/?level=enterprise
[console config]: /ko/docs/reference/console-config/
[server config]: /ko/docs/reference/server-config/

## GitHub 앱 생성

- [GitHub 앱](https://docs.github.com/ko/apps/creating-github-apps/registering-a-github-app/registering-a-github-app#registering-a-github-app) 생성
- GitHub 앱 이름
  - 고유한 이름 선택 (예: `My Enterprise용 Bencher`)
- 홈페이지 URL
  - 이를 Bencher Self-Hosted 콘솔 URL로 설정 (예: `https://bencher.example.com`)
- 사용자 식별 및 인증
  - 콜백 URL
    - 콜백 URL을 `/auth/github` 경로를 가진 Bencher Self-Hosted 콘솔 URL로 설정 (예: `https://bencher.example.com/auth/github`)
  - ✅ 사용자 인증 토큰 만료
  - ✅ 설치 도중 사용자 인증 (OAuth) 요청
  - ✅ 디바이스 흐름 활성화
- 웹훅
  - ❌ 활성화 - 이 상자의 체크를 해제
- 권한
  - 계정 권한
    - 이메일 주소: `읽기 전용`
- 이 GitHub 앱을 어디에 설치할 수 있는가?
  - 🔘 모든 계정
- `GitHub 앱 생성` 클릭
- 이제 새로 생성된 앱의 `일반`으로 가기
- `Client ID`를 기재해 두세요 (예: `Iv1.12864abcd1232048`)
- 클라이언트 비밀 유지
  - `새 클라이언트 비밀 생성` 클릭
  - 이 비밀을 기재해 두세요 (예: `00000abcd12345wxyz123456789abcdefgh0000`)
- [Bencher 로고 PNG](/brand/)를 디스플레이 정보 아래에 추가
- 비공개 키
  - `비공개 키 생성` 클릭

## GitHub 앱 구성

### 콘솔 UI
`bencher-console` Docker 이미지를 실행할 때 `GITHUB_CLIENT_ID` 환경 변수를 설정합니다. (예: `GITHUB_CLIENT_ID=Iv1.12864abcd1232048`) 만약 클라이언트 ID가 누락되면, UI에 GitHub 버튼이 표시되지 않습니다.

### API 서버
`client_id`와 `client_secret`를 [서버 구성의 `plus.github` 섹션](/ko/docs/reference/server-config/#plusgithub)에 추가합니다. 만약 GitHub 섹션이 누락되면, 서버는 GitHub 인증 요청을 실패시킵니다.

## 연결된 저장소

이 설정에는 `v0.6.18` 이상의 Bencher Self-Hosted API 서버와 콘솔이 필요합니다.

프로젝트가 분리된 실행을 위해 [GitHub 저장소를 연결][linked repository]할 수 있게 하려면 GitHub 앱에 다음도 설정합니다.

- 사용자 식별 및 인증
  - 콜백 URL
    - 첫 번째 콜백 URL을 `/console/github` 경로를 가진 Bencher Self-Hosted 콘솔 URL로 설정 (예: `https://bencher.example.com/console/github`).
      GitHub는 앱을 설치한 사용자를 첫 번째 콜백 URL로 보냅니다.
    - 그 뒤에 로그인을 위한 `/auth/github` 경로의 콜백 URL을 유지 (예: `https://bencher.example.com/auth/github`).
      GitHub는 콜백 URL이 목록에 없는 로그인을 거부합니다.
  - ✅ 설치 도중 사용자 인증 (OAuth) 요청
- 웹훅
  - ✅ 활성화 - 이 상자를 체크
  - 웹훅 URL
    - `/v0/github/webhook` 경로를 가진 Bencher Self-Hosted API 서버 URL로 설정 (예: `https://api.bencher.example.com/v0/github/webhook`)
  - 웹훅 시크릿
    - 임의의 시크릿을 입력하고 기재해 두세요 (예: `0123456789abcdef0123456789abcdef`)
- 권한
  - 저장소 권한
    - Checks: `읽기 및 쓰기`
    - 콘텐츠: `읽기 전용`
    - Pull requests: `읽기 및 쓰기`
  - 이벤트 구독
    - 모든 이벤트를 체크하지 않은 상태로 두기
- 앱의 슬러그, 즉 공개 페이지 URL의 마지막 부분을 기재해 두세요 (예: `https://github.com/apps/my-bencher-app`의 `my-bencher-app`)

슬러그, 비공개 키, 웹훅 시크릿을 [서버 구성의 `plus.github` 섹션](/ko/docs/reference/server-config/#plusgithub)에 `app`으로 추가합니다.

이전 버전에서 콘텐츠: `읽기 및 쓰기`로 설정한 앱을 업데이트하려면:

1. 업그레이드 전에 Checks와 Pull requests를 추가합니다.
   GitHub는 각 설치의 소유자에게 이를 승인하도록 요청합니다.
2. API 서버와 콘솔을 `v0.6.18` 이상으로 업그레이드합니다.
   업그레이드 후, 설치가 새 권한을 승인하지 않은 저장소는 연결할 수 없으며, Bencher는 그 저장소에 게시할 수 없습니다.
3. 별도의 변경으로 콘텐츠를 `읽기 전용`으로 변경합니다.

## GitHub Enterprise Server

github.com 대신 GitHub Enterprise Server를 사용하려면 위의 설정으로 GitHub Enterprise Server에 GitHub 앱을 등록합니다.
그런 다음 [서버 구성의 `plus.github` 섹션](/ko/docs/reference/server-config/#plusgithub)에서 `server_url`을 그 웹 루트로 설정합니다 (예: `https://github.example.com`).
그러면 Bencher는 로그인, 연결된 저장소, 커밋 제목, 그리고 분리된 실행의 GitHub Check와 pull request 댓글에 이를 사용합니다.
앱의 slug는 공개 페이지 URL의 마지막 부분입니다 (예: `https://github.example.com/github-apps/my-bencher-app`의 `my-bencher-app`).

이를 위해서는 `v0.6.18` 이상의 Bencher Self-Hosted API 서버와
서버의 하나 이상의 조직에 대한 유효한 Bencher Plus Enterprise 라이선스가 필요합니다.
라이선스가 없으면 Bencher는 GitHub 로그인, 연결, GitHub Actions의 분리된 실행을 거부하고 커밋 제목을 가져오지 않습니다.
Bencher는 워크플로가 같은 GitHub Enterprise Server에서 실행될 때만 분리된 실행의 결과를 게시합니다.
`GITHUB_API_URL`이 다른 GitHub의 API인 실행은 거부합니다.
